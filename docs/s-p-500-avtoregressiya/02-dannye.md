# 2. Данные и аудит утечек

Senior не доверяет данным, пока не проверил их. В этом уроке — аудит датасета и
поиск утечек до того, как появится первая модель.

!!! abstract "Артефакт урока"
    Data audit: происхождение, диапазон, пропуски, аномалии, утечки, ограничения.

## Как думает senior

Он не спрашивает «есть ли пропуски». Он спрашивает: «были ли эти данные доступны
в момент прогноза и что будет, если источник обновится задним числом». Данные —
это контракт, а не файл.

## Твоя очередь

## Шаг 1 · Загрузи и посмотри

```python
import pandas as pd
import numpy as np

URL = "https://datahub.io/core/s-and-p-500/r/data.csv"
df = pd.read_csv(URL, parse_dates=["Date"]).sort_values("Date").reset_index(drop=True)

print(df.shape)
print(df["Date"].min(), df["Date"].max())
print(df.isna().sum())
```

!!! question "Сделай"
    Сколько строк, какой диапазон дат, есть ли пропуски?

??? success "Проверить"
    Около `1869` строк, `1871-01-01 … 2026-09-01`. В `SP500` пропусков нет.
    В остальных столбцах после `2023-07` стоят нули — это не пропуски, а
    особенность источника.

## Шаг 2 · Проверь, что данные point-in-time

Главный вопрос аудита: **были ли эти данные доступны в момент прогноза?**

```python
# пример: что реально лежит в конце ряда
print(df.tail(8)[["Date", "SP500", "Dividend", "Earnings", "PE10"]])
```

!!! warning "Ловушка"
    `PE10` после `2023-07` равен `0`, потому что источник не обновил остальные
    поля. Если использовать `PE10` как признак, модель увидит «ноль» вместо
    реального значения и выучит артефакт источника.

!!! question "Сделай"
    Какие столбцы можно использовать без оговорок, а какие требуют обрезки ряда?

??? success "Проверить"
    `SP500` — можно. `Dividend`, `Earnings`, `PE10`, `Real *` — только до
    `2023-06`, иначе нули. Всё, что пересчитывается задним числом (реальные
    значения, дефляторы), требует отдельной проверки на look-ahead.

## Шаг 3 · Проверь диапазоны и аномалии

```python
print(df["SP500"].describe())
print(df[df["SP500"] <= 0])
print(df["SP500"].pct_change().abs().nlargest(5))
```

!!! question "Сделай"
    Есть ли нулевые или отрицательные цены? Какие месяцы дали самые большие
    изменения?

??? success "Проверить"
    Нулей и отрицательных цен быть не должно. Крупнейшие изменения — кризисы
    (`1929`, `1987`, `2008`, `2020`). Это не ошибки, но они сильно влияют на
    RMSE.

## Шаг 4 · Проверь частоту и непрерывность

```python
gaps = df["Date"].diff().dt.days
print(gaps.value_counts().head())
print("пропущенных месяцев:", (gaps > 31).sum())
```

!!! question "Сделай"
    Ряд действительно месячный и без пропусков?

??? success "Проверить"
    Шаг около `28–31` дня, крупных разрывов нет. Если бы были — нужна
    ресемплинация и явное решение, как заполнять.

## Шаг 5 · Найди утечки в признаках

Чек-лист:

- [ ] признаки не пересчитываются задним числом;
- [ ] нет `shift(-k)`;
- [ ] нет статистик, посчитанных на всём ряде (среднее, масштаб);
- [ ] нет данных, которых не было в момент прогноза;
- [ ] test не участвует в预处理.

```python
# плохо: масштаб посчитан на всём ряде
# good: только на train
train = df[df["Date"] <= "1979-12-31"]
mu = train["ret"].mean()
sigma = train["ret"].std()
```

!!! warning "Ловушка"
    Нормировка по всему ряду — классическая утечка. Модель «знает» будущее
    среднее и показывает завышенное качество.

## Шаг 6 · Напиши data audit

```md
# Data audit: S&P 500

## Источник
DataHub / Shiller + FRED. Месячные данные, 1871–2026.

## Что используем
SP500 → лог-доходность.

## Ограничения
- после 2023-07 остальные поля = 0;
- ранняя часть — реконструкция, не официальный индекс;
- нет транзакционных издержек и дивидендов в целевой метрике.

## Проверки
- пропуски: 0;
- цены > 0: да;
- частота: месячная, разрывов нет;
- утечки: перечислены и закрыты.

## Решение
Использовать только SP500. Остальные признаки — вне рамок первой итерации.
```

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| point-in-time | данные в том виде, в каком были доступны тогда |
| look-ahead bias | использование будущего |
| data audit | проверка данных до модели |
| leakage | утечка информации |

- [ ] решение по каждому столбцу записано.
