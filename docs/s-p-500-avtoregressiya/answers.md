# Ответы и разборы

Здесь ответы на тест и полный инженерный разбор. Но помни: цель курса — не
совпасть с ответом, а научиться принимать решение.

## Ответы теста самопроверки

1. Чтобы понять, есть ли от модели польза; без baseline сравнение бессмысленно.
2. Обучение на прошлом и проверка на следующем окне со сдвигом вперёд.
3. Тогда он участвует в выборе и перестаёт быть независимой проверкой.
4. Шум неустраним и не имеет структуры; смена режима — систематическое изменение
   свойств ряда.
5. Решение, доказательства, ограничения, риски, условия пересмотра.
6. Когда гипотезы исчерпаны или нет данных для проверки; stop экономит ресурсы.
7. Улучшение может быть меньше разброса между окнами, то есть шумом.
8. Отключение одного компонента, чтобы измерить его вклад.
9. Нормировка по всему ряду, заполнение пропусков будущим, отбор признаков по
   всему датасету.
10. Почему это решение; откуда знаешь, что работает; что сломается первым.

## Разбор полного решения

### Что должно быть в ноутбуке

1. Бриф и протокол — до кода.
2. Data audit с ограничениями источника.
3. Baseline на walk-forward.
4. AR с журналом экспериментов.
5. Ablation.
6. Error analysis по режимам.
7. Memo и ревью.

### Ключевые числа

- средняя лог-доходность ≈ `0.004`;
- std ≈ `0.04`;
- RMSE baseline и модели различаются в третьем-четвёртом знаке;
- directional accuracy около `0.5`.

Эти числа не «ответ», а ориентир. Если у тебя сильно иначе — проверь протокол.

## Как выглядит сильный вывод

> «AR(3) на месячной лог-доходности не даёт устойчивого преимущества над random
> walk: RMSE `0.0398` против `0.0401`, но разброс по окнам `0.003`, и модель
> лучше лишь в 54 % окон. Directional accuracy `0.502`. В кризисные периоды
> ошибка вырастает в 3–5 раз. Решение: stop для торгового сигнала; iterate как
> учебное исследование режимных признаков».

## Как выглядит слабый вывод

> «Модель показала R² 0.99, значит, отлично предсказывает S&P 500».

Здесь три ошибки: `R²` на цене, нет baseline, нет out-of-sample.

## Типичные инженерные ошибки

| Ошибка | Severity | Почему |
| --- | --- | --- |
| оценка на train | blocker | нет доказательства обобщения |
| выбор `p` по тесту | blocker | тест перестал быть тестом |
| нормировка по всему ряду | blocker | look-ahead |
| нет baseline | major | не с чем сравнивать |
| только средняя метрика | major | не видно устойчивости |
| нет error analysis | major | непонятно, где ломается |
| нет seed/версий | major | невоспроизводимо |
| «модель хорошая» без чисел | major | решение не проверяемо |
| длинные функции без имён | minor | поддержка |
| закомментированный код | minor | мусор |

## Что улучшить в следующей итерации

- режимные признаки (волатильность, ставка);
- GARCH для волатильности отдельно от доходности;
- несколько горизонтов;
- сравнение с `AutoReg` и информационными критериями;
- тест Diebold-Mariano на значимость разницы прогнозов.
