# 3. Повторный запуск скрипта

Требование «скрипт можно запускать повторно» ломает новичков чаще всего. После
урока ты поймёшь, почему второй запуск падает, и как это исправить.

## Почему второй запуск падает

Первый запуск создал таблицу `positions`. Второй запуск пытается создать её
снова:

```sql
CREATE TABLE positions (...);
```

СУБД отвечает ошибкой: `relation "positions" already exists`. Скрипт
останавливается.

!!! note "Определение"
    **Идемпотентность** — свойство операции давать одинаковый результат при
    повторном выполнении. Скрипт-идемпотент запускается сколько угодно раз без
    ошибок.

## Решение — DROP перед CREATE

Перед созданием удаляем старую таблицу:

```sql
DROP TABLE IF EXISTS positions;
CREATE TABLE positions (...);
```

`DROP TABLE` удаляет таблицу целиком — и структуру, и данные. `IF EXISTS`
означает «удалить, если существует»: на первом запуске таблицы нет, и команда
молча пропускается вместо ошибки.

!!! warning "IF EXISTS — расширение СУБД"
    В строгом ANSI-92 у `DROP TABLE` нет `IF EXISTS`. Практически его
    поддерживают PostgreSQL, MySQL, MS SQL. В задании такой вариант принимают;
    если преподаватель требует строгий стандарт — скажи, разберём обходной путь.

## Порядок удаления

Сначала удаляем «дочерние» таблицы, потом «родительские». Иначе внешний ключ
запретит удаление.

```text
DROP parameters
DROP packs
DROP users
DROP equipment_types
DROP positions
```

`packs` ссылается на `users`, поэтому `packs` удаляется раньше. Полная схема
связей — в уроке 4.

!!! danger "Порядок важен"
    Если удалить `users` раньше `packs`, СУБД откажет: на `users` ссылается
    внешний ключ из `packs`. Удаляй строго в обратном порядке зависимостей.

## Каркас скрипта

Теперь файл начинается так:

```sql
-- 1. Очистка в обратном порядке связей
DROP TABLE IF EXISTS parameters;
DROP TABLE IF EXISTS packs;
DROP TABLE IF EXISTS users;
DROP TABLE IF EXISTS equipment_types;
DROP TABLE IF EXISTS positions;

-- 2. Создание таблиц (порядок разберём в уроке 4)
CREATE TABLE positions (...);
-- ...

-- 3. Данные
INSERT INTO positions (...) VALUES (...);
-- ...
```

## Проверка

Запусти скрипт дважды подряд. Если оба раза прошли без ошибок — требование
выполнено.

## Частые ошибки

!!! warning "Ошибка"
    Удалять таблицы в том же порядке, в котором создаёшь. При связях это даёт
    ошибку внешнего ключа. Правило: создаём родителей первыми, удаляем —
    последними.

!!! warning "Ошибка"
    Писать `DROP TABLE` без `IF EXISTS`. Первый запуск тогда упадёт.
