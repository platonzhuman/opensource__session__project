## Как думает senior

Сначала фиксирует условия сравнения, потом запускает. Если условие поменялось
между методами — результат недействителен, каким бы красивым он ни был.

## Шаг 2 · Единый запуск

```python
import time

def measure(name, cls, kwargs):
    t0 = time.perf_counter()
    r = run(cls, **kwargs)
    elapsed = time.perf_counter() - t0
    return {
        "method": name,
        "x": round(r["x"], 4),
        "y": round(r["y"], 4),
        "f": round(r["f"], 4),
        "steps": steps_to(r["losses"]),
        "time_s": round(elapsed, 4),
        **r,
    }

rows = [measure(*m) for m in methods]
```

!!! question "Сделай"
    Почему время нужно мерить на одной машине и одном окружении?

??? success "Проверить"
    Иначе сравнение бессмысленно: разные CPU, фоновые процессы, версии `torch`.

## Шаг 3 · Таблица результатов

```python
import pandas as pd

table = pd.DataFrame([
    {k: r[k] for k in ["method", "x", "y", "f", "steps", "time_s"]}
    for r in rows
]).sort_values("f")
print(table.to_string(index=False))
```

!!! question "Сделай"

??? success "Проверить"
    Большинство достигает `-1`. RMSprop может остановиться на `-0.997`,
    Adadelta при `lr=0.1` — почти не сдвинуться. Запиши фактическую картину.

## Шаг 4 · Раздели исходы

| Исход | Что значит | Как трактовать |
| --- | --- | --- |
| `f ≈ -1`, быстро | метод сходится | кандидат |
| `f ≈ -1`, медленно | сходится, но дорого | кандидат с оговоркой |
| `f > -0.99` | не дошёл за бюджет | не подходит при данном бюджете |
| расхождение | нестабилен | не подходит без настройки |

!!! warning "Ловушка"
    Выкинуть «неудобные» методы из таблицы. Расходящийся метод — важный
    результат: он показывает границы применимости.

## Шаг 5 · Проверь устойчивость

Для топ-3 методов:

```python
for name, cls, kw in methods[:3]:
    for lr in [0.08, 0.1, 0.12]:
        r = run(cls, lr=lr, **kw)
        print(name, lr, round(r["f"], 4), steps_to(r["losses"]))
```
