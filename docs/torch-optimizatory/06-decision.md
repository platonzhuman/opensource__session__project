# 6. Решение

Финальный шаг: выбрать оптимизатор и защитить выбор. Не «вот таблица», а
рекомендация с условиями.

!!! abstract "Артефакт урока"
    Memo с рекомендацией и ревью по рубрике.

## Как думает senior

Он даёт рекомендацию с условиями: для какого класса задач, при каком бюджете,
что проверить перед применением.

## Твоя очередь

## Шаг 1 · Проверь воспроизводимость

```python
import torch

torch.manual_seed(0)
```

Чек-лист:

- [ ] ноутбук запускается сверху вниз;
- [ ] зафиксирован seed;
- [ ] указаны версии `torch` и Python;
- [ ] время измерено на одной машине;
- [ ] таблица и графики строятся из одного прогона.

!!! warning "Ловушка"
    «У меня Adam быстрее» без указания версии и машины. Через месяц результат
    не воспроизведётся.

## Шаг 2 · Сформулируй рекомендацию

```md
# Memo: выбор оптимизатора

## Вопрос
Какой оптимизатор брать по умолчанию для гладкой невыпуклой функции
с двумя параметрами при бюджете 1000 шагов?

## Доказательства
- baseline SGD: steps_to(-0.99) = 39, final f = -1.0000
- Adam: steps_to(-0.99) = 25, final f = -1.0000
- RMSprop: steps_to = 4, final f = -0.9974
- Adadelta: final f = -0.077 (не сошёлся)

## Интерпретация
Adam быстрее baseline и попадает точно в минимум. RMSprop ещё быстрее,
но не доходит до -1, поэтому для критерия «f < -0.99» не подходит.

## Ограничения
- только 2 параметра;
- только гладкая функция;
- один lr;
- нет стохастических градиентов.

## Решение
По умолчанию — Adam. Если важен точный минимум при малом бюджете —
проверить RMSprop с меньшим lr.

## Когда пересмотреть
На нейросетях, при шумных градиентах, при больших моделях — протокол
нужно повторить.
```

!!! question "Сделай"
    Почему RMSprop «быстрее», но не выигрывает?

??? success "Проверить"
    Потому что критерий — достичь `f < -0.99`. Быстро подойти и остановиться на
    `-0.997` — не то же самое, что сойтись.

## Шаг 3 · Пройди рубрику

[Рубрика](../standards/review-rubric.md). Выпиши замечания:

```md
| # | severity | замечание | где | как исправить |
| --- | --- | --- | --- | --- |
```

Типичные:

- `[blocker]` разный `lr` у методов;
- `[major]` нет baseline;
- `[major]` нет устойчивости;
- `[minor]` нет времени;
- `[nit]` подписи на графиках.

## Шаг 4 · Подготовь защиту

1. Почему Adam, а не SGD?
2. Откуда знаешь, что он работает?
3. Что сломается первым?

!!! question "Сделай"
    Ответь на три вопроса за 2 минуты, используя числа.

??? success "Проверить"
    Хороший ответ: «Adam достигает порога за 25 шагов против 39 у SGD, устойчив
    при `lr ± 20 %`, но на шумных градиентах вывод надо перепроверить».

## Шаг 5 · Что приложить

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| memo | рекомендация с условиями |
| rubric | формальная оценка |
| защита | устное обоснование |
| условия пересмотра | когда вывод устареет |

## Критерии приёмки

- [ ] ноутбук воспроизводится;
- [ ] рекомендация сформулирована;
- [ ] есть числа и ограничения;
- [ ] ревью пройдено;
- [ ] ответы на защиту готовы.
