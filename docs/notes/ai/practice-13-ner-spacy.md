# NER: BIO-разметка и spaCy

## О чём эта запись

Две практики об одной задаче — извлечении именованных сущностей (Named Entity Recognition, NER). В первой строится собственная модель для кулинарных рецептов: текст уже разбит на слова, каждому приписан тег BIO, и сеть `Embedding → LSTM → Dense` учится их предсказывать. Разбираются формат датасета, конвертация в индексы, архитектура, обучение и матрица ошибок. Во второй та же задача решается готовой моделью spaCy: из «Моби Дика» вырезается глава, первые 100 предложений подаются в `en_core_web_sm`, сущности выводятся списком и через `displacy`.

Смысл пары: сравнить NER «с нуля» на доменном датасете и NER «из коробки» на предобученной модели.

## Главные идеи

- NER — это разметка последовательности: каждому токену назначается класс сущности, а не всей строке один класс.
- Схема BIO: `B-` начинает сущность, `I-` продолжает её, `OTHER` (аналог `O`) означает «вне сущности».
- В рецептах размечены количества (`QTY`), единицы (`UNIT`), названия ингредиентов (`NAME`), комментарии (`COMMENT`), индексы (`INDEX`) и концы диапазонов (`RANGE_END`).
- Модель в ноутбуке сжимает шесть слов в один вектор LSTM и разворачивает его в 60 логитов; это упрощение, а не полноценный token classification.
- `Softmax(axis=1)` в этой модели нормирует вероятности по позициям, а не по тегам, что не соответствует попозиционной кросс-энтропии.
- Качество на 666 токенах: accuracy 0.70, macro F1 0.53; хорошо работают частые классы `B-QTY`, `B-UNIT`, `B-NAME`, редкие — почти не предсказываются.
- spaCy даёт готовые типы `PERSON`, `GPE`, `DATE`, `CARDINAL`, `NORP` и другие, но без обучения на домене и с ошибками на неоднозначных словах.

## Полный разбор

### 1. Задача NER и схема BIO

Извлечение именованных сущностей отвечает на вопрос, какие фрагменты текста являются именами, организациями, датами, суммами. В отличие от классификации всего текста, здесь нужен ответ для каждого слова, поэтому задача формулируется как **разметка последовательности**: на входе список токенов, на выходе список тегов той же длины.

Схема BIO кодирует границы сущности:

- `B-X` — первый токен сущности типа `X` (begin);
- `I-X` — продолжение сущности типа `X` (inside);
- `O` — вне сущности (outside). В этом датасете вместо `O` используется `OTHER`.

Пример из ноутбука:

```text
1$1/4      B-QTY
cups       B-UNIT
cooked     B-COMMENT
and        I-COMMENT
butternut  B-NAME
squash     I-NAME
,          OTHER
```

Читается так: количество — `1$1/4`, единица — `cups`, комментарий начинается на `cooked` и продолжается на `and`, название ингредиента — «butternut squash», запятая — вне сущности.

Схема BIO решает проблему склеивания соседних сущностей одного типа: если бы все токены имени были помечены просто `NAME`, два стоящих рядом названия слились бы в одно. `B-` начинает новую сущность, `I-` продолжает.

### 2. Формат датасета

```python
datafile = 'files/BIO_recipe_dataset.txt'
lines = open(datafile, encoding='utf-8').read().strip().split('\n')
```

Файл читается целиком, обрезается по краям и делится по переводу строки. Каждая непустая строка — «слово табуляция тег», пустая строка разделяет рецепты.

```python
def form_vocabulary_and_tagset(recipes):
    dictionary = set()
    labels = set()
    for line in recipes:
        if len(line) > 0:
            word, label = line.split('\t')
            dictionary.add(word)
            labels.add(label)
    return dictionary, labels

vocabulary, labels = form_vocabulary_and_tagset(lines)
```

`set` убирает повторы: словарь — это все уникальные слова, а не все вхождения. `line.split('\t')` делит строго по табуляции; если в слове встретится табуляция, разбор сломается, но в этом датасете такого нет.

Получается 5 194 уникальных слова и 10 тегов: `B-QTY`, `B-UNIT`, `B-NAME`, `B-COMMENT`, `B-INDEX`, `B-RANGE_END`, `I-COMMENT`, `I-NAME`, `I-UNIT`, `OTHER`. Обратите внимание: `I-QTY`, `I-INDEX`, `I-RANGE_END` отсутствуют — такие сущности всегда длины 1 или размечены иначе.

Смысл тегов: `QTY` — количество («1», «1$1/2»); `UNIT` — единица («cups», «stalks»); `NAME` — название ингредиента; `COMMENT` — комментарий: нарезка, состояние, уточнение («cooked», «frozen»); `RANGE_END` — конец диапазона в «2-3»; `INDEX` — числовой индекс, точный смысл которого по одному примеру не восстановить (иногда стоит там, где ожидается `QTY`, — это особенность датасета); `OTHER` — запятые, союзы, предлоги.

Токенизация уже сделана, знаки препинания — отдельные токены: модель не режет текст на слова, она получает готовые.

### 3. Сборка рецептов

```python
def prepare_data(lines):
    recipes_w_tags = []
    recipe, tags = [], []
    for line in lines:
        if len(line) > 0:
            word, label = line.split('\t')
            recipe.append(word)
            tags.append(label)
        else:
            if len(recipe) > 0:
                recipes_w_tags.append((recipe, tags))
            recipe, tags = [], []
    return recipes_w_tags

recipes_w_tags = prepare_data(lines)
print(recipes_w_tags[:5])
len(recipes_w_tags)
```

Функция накапливает слова и теги, пока не встретит пустую строку, затем сохраняет пару списков и начинает новую. Результат — 49 847 рецептов. В первом рецепте интересно, что после `or` снова идёт `B-NAME` для `squash`, а `1` и `10-ounce package frozen` помечены как `I-COMMENT`. Разметка не идеальна, и модель учится в том числе на её шуме.

Есть пограничный случай: если файл не заканчивается пустой строкой, последний рецепт не будет добавлен. В коде это не обработано; при 49 847 записях потеря одного рецепта незаметна, но в общем случае это ошибка.

### 4. Визуализация разметки

Для проверки разметки используется `ipymarkup`: `show_markup` склеивает слова через пробел, срезает у тегов префиксы `B-` и `I-`, чтобы сущность красилась одним цветом, и вычисляет **символьные смещения** начала и конца каждого отрезка. Когда тег меняется, текущий отрезок сохраняется и начинается новый. Смещения считаются по длинам слов плюс пробелы, потому что `ipymarkup` работает с позициями в строке. Функция полезна для отладки: рядом выводятся истинная и предсказанная разметка.

### 5. Конвертер слов и тегов

Модель не работает со строками, поэтому нужен словарь «строка → номер». Класс `Converter` сортирует словарь и теги, строит прямые и обратные отображения и умеет переводить список слов в массив `int32`, а индексы — обратно в теги. Сортировка делает отображение детерминированным: при повторном запуске те же слова получат те же номера. Без неё порядок зависел бы от входа в `set`.

Здесь есть скрытая ошибка. Значение по умолчанию `max_words=-1`, а условие `len(words) >= max_words` при `max_words=-1` всегда истинно. Тогда срез `[: -1]` отбрасывает **последнее** слово, а не «все слова». Если вызвать `words_to_index(recipe)` без второго аргумента, результат будет неполным. В ноутбуке везде передаётся `max_words=MAX_WORDS`, поэтому ошибка не проявляется, но это классическая ловушка с значением по умолчанию.

Вторая особенность: если `len(words) < max_words`, возвращается массив короче `max_words`, и форма не совпадает с ожидаемой моделью. Поэтому при обучении отбираются только рецепты длиной не меньше `MAX_WORDS`.

Пример кодирования первого рецепта: `er: [57, 2245, 2133, 1520, 4060, 2650, …]`, `et: [3, 5, 0, 6, 6, 6, …]`. Числа — индексы в отсортированных словарях; `3` соответствует `B-QTY`, `5` — `B-UNIT`, `0` — `B-COMMENT` (точное соответствие зависит от сортировки).

### 6. Архитектура модели

```python
EMBEDDING_DIM = 32
HIDDEN_DIM = 30
VOCAB_SIZE = len(converter.word_to_idx)      # 5194
TAGSET_SIZE = len(converter.tag_to_idx)      # 10

import tensorflow as tf
MAX_WORDS = 6

model = tf.keras.models.Sequential()
model.add(tf.keras.layers.Input(shape=(MAX_WORDS,)))
model.add(tf.keras.layers.Embedding(VOCAB_SIZE, EMBEDDING_DIM))
model.add(tf.keras.layers.LSTM(HIDDEN_DIM))
model.add(tf.keras.layers.Dense(MAX_WORDS * TAGSET_SIZE))
model.add(tf.keras.layers.Reshape((MAX_WORDS, TAGSET_SIZE)))
model.add(tf.keras.layers.Softmax(axis=1))
print(model.summary())
```

Разберём по слоям.

`Embedding(5194, 32)` превращает номер слова в обучаемый вектор длины 32. Это компактнее one-hot на 5194 позиции и позволяет близким по смыслу словам получать близкие векторы.

`LSTM(30)` читает шесть векторов и возвращает **один** вектор длины 30 — последнее состояние. По умолчанию `return_sequences=False`, поэтому последовательность исчезает: остаётся её сжатое описание.

`Dense(60)` выдаёт 60 чисел — по 10 на каждую из 6 позиций. `Reshape((6, 10))` разворачивает их в таблицу «позиция × тег». `Softmax(axis=1)` нормирует по оси позиций.

Параметры: `Embedding` — $5194 \cdot 32 = 166\,208$; `LSTM` — $4 \cdot ((32 + 30) \cdot 30 + 30) = 7560$; `Dense` — $30 \cdot 60 + 60 = 1860$. Итого $175\,628$, как в `summary`.

У этой архитектуры два концептуальных недостатка. Во-первых, после LSTM остаётся один вектор на весь рецепт, поэтому различия между позициями восстанавливаются только из него; нормальная token classification использует `return_sequences=True`, чтобы у каждой позиции было своё состояние. Во-вторых, `Softmax(axis=1)` нормирует вероятности **по шести позициям** для каждого тега, а не по десяти тегам для каждой позиции; для попозиционной кросс-энтропии нужна `axis=-1`. Модель всё равно обучается, но это учебное упрощение, а не правильная схема.

### 7. Что модель видит на самом деле

```python
encoded_recipe, encoded_tags = [], []
p = []
for i, (recipe, tags) in enumerate(training_data):
    p.append(len(recipe))
    if len(recipe) >= MAX_WORDS:
        encoded_recipe.append(converter.words_to_index(recipe, max_words=MAX_WORDS))
        tags = converter.tags_to_index(tags, max_words=MAX_WORDS)
        encoded_tags.append(
            tf.keras.utils.to_categorical(tags, num_classes=TAGSET_SIZE))

encoded_recipe = np.array(encoded_recipe)
encoded_tags = np.array(encoded_tags)
print(encoded_recipe.shape)
print(encoded_tags.shape)
```

`MAX_WORDS = 6` переопределяет более раннее значение 48 (максимальная длина рецепта). Обучение идёт только на рецептах длиной не меньше 6, и от каждого берутся **первые шесть токенов**. Получается 15 733 примера формы `(15733, 6)` и метки `(15733, 6, 10)` после one-hot.

Это важное ограничение: модель никогда не видит середину и конец рецепта. В первых шести токенах обычно стоят количество, единица и начало комментария; название ингредиента часто попадает, но не всегда. Отсюда и распределение качества: частые классы начала строки предсказываются хорошо, редкие — плохо.

### 8. Обучение

```python
model.compile(optimizer='adam', loss='categorical_crossentropy',
              metrics=[tf.keras.metrics.AUC(curve='PR')])
callback = tf.keras.callbacks.EarlyStopping(
    monitor='val_loss', mode='min', patience=3, restore_best_weights=True)
model.fit(encoded_recipe, encoded_tags, validation_split=0.2,
          epochs=100, callbacks=[callback])
```

`categorical_crossentropy` сравнивает распределение по 10 тегам с one-hot целью на каждой из 6 позиций. `AUC(curve='PR')` — площадь под кривой precision-recall; для многоклассового выхода Keras усредняет по классам, поэтому метрика не так информативна, как для бинарной задачи.

`EarlyStopping` следит за `val_loss`, терпит три эпохи без улучшения и возвращает лучшие веса. В логе:

### 9. Оценка: 300 рецептов и 666 токенов

Цикл 300 раз выбирает случайный рецепт из `test_data`, пропускает короткие и накапливает истинные и предсказанные теги. Тестовая часть — 9 847 рецептов, индексы берутся из первых 7000, поэтому часть теста не используется. Каждый рецепт даёт 6 предсказаний, всего 666 токенов.

def predict_tags(model, converter, recipe):

### 10. Отчёт и перепутанные аргументы

```python
from sklearn.metrics import classification_report
classification_report(yp_arr, yt_arr)
```

Здесь допущена ошибка: первым аргументом должно быть истинное `yt_arr`, вторым — предсказание `yp_arr` (сигнатура `classification_report(y_true, y_pred)`). Из-за перестановки accuracy остаётся правильной, precision и recall меняются местами, а `support` показывает число предсказаний, а не истинных объектов.

Вывод:

```text

      B-NAME       0.74    0.86      0.80       95
       B-QTY       0.98    0.93      0.95      102

```

Чтобы понять числа, посмотрим на строку `B-COMMENT` матрицы: из 139 истинных `B-COMMENT` правильно предсказано 66, то есть recall $66/139 = 0.47$. В отчёте это число стоит в колонке `precision` — именно потому, что аргументы переставлены. Настоящая precision — $66/86 = 0.77$, она стоит в колонке `recall`. F1 от перестановки не меняется: $2 \cdot 0.47 \cdot 0.77 / (0.47 + 0.77) \approx 0.59$. Те же пары чисел получаются для `B-QTY` (recall 0.98, precision 0.93) и `B-NAME` (recall 0.74, precision 0.86).

Итоговые выводы по качеству:

- accuracy 0.70 — доля правильно размеченных токенов;
- macro F1 0.53 — среднее по классам без учёта их размера; низкое из-за редких классов;
- weighted F1 0.68 — с учётом частот, ближе к реальному ощущению;
- сильные классы: `B-QTY` (0.95), `B-UNIT` (0.84), `B-NAME` (0.80) — они частые и стоят в начале рецепта;
- слабые: `B-RANGE_END` (0.24), `OTHER` (0.48), `B-INDEX` и `I-UNIT` (0) — редкие или отсутствующие в срезе.

666 токенов — маленькая смещённая выборка; по ней нельзя судить о модели на полных рецептах.

### 11. spaCy: готовая модель

Вторая практика начинается с загрузки модели:

```python
import spacy
nlp = spacy.load("en_core_web_sm")
print(nlp)
```

`spacy.load` загружает обученный пайплайн для английского языка. `en_core_web_sm` — маленькая версия: быстрая, но менее точная, чем `md` или `lg`. В объекте `nlp` уже есть токенизатор, разбиение на предложения и компонент NER; обучать ничего не нужно.

### 12. Вырезание главы регулярным выражением

```python
from spacy import displacy
import re

with open("files/2701-0.txt", "r", encoding="utf-8") as f:
    text = f.read()

matches = re.findall(r"CHAPTER 1\. Loomings\.(.*?)CHAPTER 2\.",
                     text, re.DOTALL)
chapter_1_text = re.sub(r"\s+", " ", matches[-1]).strip()

doc_ch1 = nlp(chapter_1_text)
first_100_sents = [sent.text for sent in list(doc_ch1.sents)[:100]]
text_100_sents = " ".join(first_100_sents)

doc2 = nlp(text_100_sents)
```

`2701-0.txt` — текст «Моби Дика» с Project Gutenberg. Шаблон ищет заголовок первой главы и **нежадно** (`.*?`) захватывает всё до заголовка второй. `re.DOTALL` позволяет точке совпадать с переводом строки, иначе захват оборвался бы на первой строке.

`matches[-1]` берётся не случайно. Заголовок «CHAPTER 1. Loomings.» встречается дважды: в оглавлении и в начале главы. Первое совпадение — короткий кусок оглавления, последнее — реальный текст главы.

`re.sub(r"\s+", " ", ...)` заменяет все последовательности пробелов, табов и переводов строк на один пробел; абзацы теряются, но для NER это допустимо. `doc_ch1.sents` — генератор предложений, `list(...)[:100]` берёт первые сто, `sent.text` возвращает их текст. Предложения склеиваются и **заново** подаются в `nlp`: это не обязательно, но гарантирует, что NER видит ровно тот текст, который получился после склейки.

### 14. Где spaCy ошибается

Разметка выглядит правдоподобно, но в ней есть явные ошибки:

- `Cato` помечен как `ORG`, хотя это человек (Катон);
- `Sabbath` — `PERSON`, хотя это день недели;
- `Niagara` — `PERSON`, хотя это водопад;
- `forecastle` — `GPE`, хотя это часть корабля;
- `Fates`, `Providence` — `GPE`, хотя это понятия/божества;
- `don’t` — `CARDINAL`, `thing;—no` — `PERSON` — мусор на границах токенов.

Причины: модель обучена на большом общем корпусе, а «Моби Дик» — проза XIX века с архаичной лексикой и необычными именами. Контекст `Niagara` может выглядеть как имя человека; модель статистическая и не знает мира, а версия `sm` уступает большим. NER всегда ошибается и на границах: `a few hours` — `TIME`, но артикль `a` вряд ли должен входить в сущность.

В ноутбуке качество spaCy не измеряется: нет размеченного набора и метрик.

### 15. Два подхода рядом

lines = open('files/BIO_recipe_dataset.txt', encoding='utf-8').read().strip().split('\n')

def prepare_data(lines):
    recipes_w_tags, recipe, tags = [], [], []
    for line in lines:
        if line:
            word, label = line.split('\t')
            recipe.append(word)
            tags.append(label)
        else:

                recipes_w_tags.append((recipe, tags))
            recipe, tags = [], []
    return recipes_w_tags

recipes_w_tags = prepare_data(lines)
training_data = recipes_w_tags[:40000]
test_data = recipes_w_tags[40000:]

vocabulary = {w for recipe, _ in recipes_w_tags for w in recipe}
labels = {t for _, tags in recipes_w_tags for t in tags}
converter = Converter(vocabulary, labels)   # класс из ноутбука

VOCAB_SIZE = len(converter.word_to_idx)
TAGSET_SIZE = len(converter.tag_to_idx)
MAX_WORDS = 6

model = tf.keras.models.Sequential([
    tf.keras.layers.Input(shape=(MAX_WORDS,)),
    tf.keras.layers.Embedding(VOCAB_SIZE, 32),
    tf.keras.layers.LSTM(30),
    tf.keras.layers.Dense(MAX_WORDS * TAGSET_SIZE),

## Формулы

| Величина | Формула | Смысл |
| --- | --- | --- |
| Precision | $P = \frac{TP}{TP + FP}$ | Доля правильных среди предсказанных |
| Recall | $R = \frac{TP}{TP + FN}$ | Доля найденных среди истинных |
| F1 | $F_1 = \frac{2PR}{P + R}$ | Гармоническое среднее precision и recall |
| Accuracy | $\text{acc} = \frac{1}{N}\sum_i [\hat{y}_i = y_i]$ | Доля правильно размеченных токенов |
| Macro F1 | $\frac{1}{K}\sum_k F_{1,k}$ | Среднее по классам, редкие классы весят столько же |
| Weighted F1 | $\sum_k \frac{n_k}{N}F_{1,k}$ | Среднее с весом по числу объектов класса |
| Softmax | $p_k = \frac{e^{z_k}}{\sum_j e^{z_j}}$ | Вероятности по тегам |
| Кросс-энтропия | $L = -\sum_k y_k \log p_k$ | Штраф за неправильный тег |
| Параметры LSTM | $4((n_{\text{in}} + n_{\text{hid}})n_{\text{hid}} + n_{\text{hid}})$ | Для $32 \to 30$: 7560 |

## Что спросят

**Что такое BIO и зачем нужны `B-` и `I-`?**
Это схема разметки последовательности: `B-X` начинает сущность типа `X`, `I-X` продолжает её, `OTHER`/`O` — вне сущности. `B-` не даёт двум соседним сущностям одного типа слиться в одну.

**Почему в датасете `OTHER`, а не `O`?**
Это просто выбранное имя для «вне сущности»; смысл тот же.

**Сколько в датасете рецептов, слов и тегов?**
49 847 рецептов, 5 194 уникальных слова, 10 тегов. Обучение — на первых 40 000, тест — остальные 9 847.

**Почему модель обучается только на шести словах?**
`MAX_WORDS = 6` переопределяет максимальную длину 48 и обрезает каждый рецепт. Это ограничение эксперимента, а не свойство задачи; из-за него модель не видит конец рецепта.

**Что не так с `Softmax(axis=1)`?**
Она нормирует вероятности по шести позициям для каждого тега, а нужна нормировка по десяти тегам для каждой позиции, то есть `axis=-1`. Иначе распределение не соответствует попозиционной кросс-энтропии.

**Почему `classification_report` в ноутбуке перепутан?**
Аргументы поданы как `(yp_arr, yt_arr)` вместо `(y_true, y_pred)`. Accuracy и F1 не меняются, а precision и recall меняются местами; `support` показывает число предсказаний.

**Зачем в spaCy `re.DOTALL` и почему `matches[-1]`?**
`DOTALL` позволяет точке захватывать переводы строк, иначе глава не вырезалась бы целиком. Заголовок встречается в оглавлении и в начале главы; последнее совпадение — настоящий текст.

**Почему spaCy путает `Niagara` и `Sabbath`?**
Модель статистическая, обучена на общем корпусе и смотрит на контекст. В прозе XIX века необычные имена и архаичные конструкции дают смещения; маленькая модель `sm` к тому же менее точна.
