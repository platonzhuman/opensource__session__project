# Деревья решений: порог, признаки, важность

## О чём эта запись

Занятие посвящено тому, как дерево решений находит границу между классами и как оно выбирает, по какому признаку делить данные. Сначала на файле `classify_sdiff.dat` строятся кумулятивные распределения двух классов и по точке их пересечения находится оптимальный порог. Затем на бинарных признаках `binary_rules.dat` показывается, как оценивается информативность каждого признака и почему дерево выбирает именно тот, который сильнее всего меняет долю положительного класса. В финале обучается `DecisionTreeClassifier` на 100000 объектов с четырьмя признаками: точность на обучающей выборке, важность признаков и первые уровни дерева.

Логика занятия: понять геометрию и статистику одного разбиения, затем увидеть, как из таких разбиений собирается дерево, и научиться читать его вывод.

## Главные идеи

- Порог между двумя классами ищется по кумулятивным распределениям: оптимален тот, где сумма «ошибок слева» и «ошибок справа» минимальна.
- Для двух классов кумулятивная кривая первого класса растёт слева направо, второго — считается справа налево; их пересечение и есть точка равновесия ошибок.
- Информативность бинарного признака оценивается по доле положительного класса в подвыборке, где признак равен 1, в сравнении с базовой долей.
- Признак, который почти не меняет долю, для разбиения бесполезен; признак, который меняет её сильно, дерево выбирает первым.
- Разбиение рекурсивно: после первого деления процесс повторяется внутри каждой ветви, и на следующем шаге может «проявиться» признак, который на всей выборке казался слабым.
- `DecisionTreeClassifier` по умолчанию строит дерево до полной чистоты листьев, поэтому на обучающей выборке точность часто равна `1.0` — это симптом переобучения.
- `feature_importances_` — нормированный вклад признака в суммарное уменьшение примеси; сумма важностей равна единице.
- `export_text` показывает пороги и классы; ветвь «меньше или равно» — левая, «больше» — правая.

## Полный разбор

### 1. Два класса и кумулятивные распределения

Первый файл — `classify_sdiff.dat`. В каждой строке два целых числа: значение признака и номер класса. Нужно найти порог $t$: если значение меньше $t$, объект относится к первому классу, если больше — ко второму. Такой классификатор называется **решающим пнём** (decision stump): одно правило, один порог, два выхода.

Код читает файл построчно, пропускает пустые строки и раскладывает числа в два массива:

```python
import numpy as np
import matplotlib.pyplot as plt

j, s = [], []
with open('files/classify_sdiff.dat', 'r') as f:
    for line in f:
        if not line.strip():
            continue
        a, b = line.split()
        j.append(int(a))
        s.append(int(b))
d1, d2 = np.array(j), np.array(s)
```

`line.split()` без аргумента делит строку по любым пробельным символам, поэтому формат «число пробел число» разбирается без указания разделителя. `int(a)` и `int(b)` превращают строки в целые — данные в файле целочисленные.

Дальше строятся две гистограммы:

```python
h1 = plt.hist(d1, density=True, cumulative=True, histtype='step',
              bins=range(-1000, 1000), label='класс 1')
h2 = plt.hist(d2, density=True, cumulative=-1, histtype='step',
              bins=range(-1000, 1000), label='класс 2')
plt.legend()
plt.title('Кумулятивные распределения двух классов')
plt.show()
```

Разберём параметры.

- `bins=range(-1000, 1000)` задаёт границы корзин: от −1000 до 999 с шагом 1. Это не «2000 корзин на глаз», а точный диапазон, в котором лежат значения.
- `density=True` нормирует гистограмму так, чтобы сумма площадей была равна единице, то есть превращает частоты в вероятности.
- `cumulative=True` даёт функцию распределения $F_1(t) = P(X \le t)$: доля объектов первого класса, у которых значение не больше $t$. Она растёт от 0 до 1.
- `cumulative=-1` даёт «обратную» кумулятивную функцию: доля объектов второго класса со значением больше либо равным $t$. Она убывает от 1 до 0.

Если выбрать порог $t$ и предсказывать «класс 1 при $x \le t$, класс 2 при $x > t$», ошибки складываются из двух частей: объекты первого класса правее порога и объекты второго класса левее. Их вероятности — $1 - F_1(t)$ и $F_2(t)$. Минимизировать эту сумму эквивалентно минимизации $F_1(t) + P_2(X > t)$: разница только в постоянном слагаемом. Именно эту сумму и считает код.

Именно это делает последняя часть:

```python
a1, a2, c2 = np.array(h1[0]), np.array(h2[0]), np.array(h2[1])
idx = np.argmin(a1 + a2)
print('порог разделения:', c2[idx])
```

`h1[0]` — значения гистограммы (для `cumulative=True` это накопленные доли), `h2[0]` — обратная кумулята, `h2[1]` — массив границ корзин. `np.argmin` находит индекс, где сумма минимальна, а `c2[idx]` возвращает соответствующую границу. Вывод ноутбука:

```text
порог разделения: 107.0
```

Почему `107.0`, а не `107.5`? Потому что `c2[idx]` — это левая граница корзины, в которой достигнут минимум. При целочисленных данных и шаге корзины 1 такая граница и есть значение порога: всё, что меньше либо равно 107, относится к одному классу, всё, что больше, — к другому. На практике после выбора порога полезно явно посчитать матрицу ошибок или accuracy, потому что минимум суммы кумулят — это эвристика, а не гарантированно максимальная accuracy.

Важно, что этот способ работает для одного признака и двух классов. Для нескольких признаков перебор всех порогов по всем признакам — уже полноценный поиск разбиения, а для многоклассовой задачи кумулятивные кривые нужно строить иначе (one-vs-rest или по каждой паре классов).

### 2. Как дерево выбирает признак

Второй файл — `binary_rules.dat`. Здесь несколько бинарных признаков (0/1) и метка класса в последнем столбце. Сначала считается базовая доля положительного класса на всей выборке:

```python
d = []
with open('files/binary_rules.dat') as f:
    for line in f:
        if line.strip():
            d.append([int(x) for x in line.split()])
d = np.array(d)
X, Y = d[:, :-1], d[:, -1]

print('доля положительных (p0):', round(float(Y.mean()), 4))
for i in range(X.shape[1]):
    print(f'  признак {i} == 1 -> доля {Y[X[:, i] == 1].mean():.4f}')
```

`d[:, :-1]` — все столбцы, кроме последнего, это матрица признаков $X$. `d[:, -1]` — последний столбец, вектор меток $Y$. `Y.mean()` для меток 0/1 даёт долю единиц. Вывод:

```text
доля положительных (p0): 0.245
  признак 0 == 1 -> доля 0.2296
  признак 1 == 1 -> доля 0.2557
  признак 2 == 1 -> доля 0.5000
  признак 3 == 1 -> доля 0.4960
  признак 4 == 1 -> доля 0.2626
```

Базовая доля $p_0 = 0.245$ означает, что если всегда предсказывать «0», accuracy будет $1 - 0.245 = 0.755$. Это важный ориентир: модель должна обыгрывать 75,5%, иначе она бесполезна.

Теперь смотрим на условные доли. Если признак 0 равен 1, доля положительных падает до 0.2296 — почти не отличается от базовой. Признак 1 даёт 0.2557, признак 4 — 0.2626: тоже слабый сдвиг. А признаки 2 и 3 дают около 0.5 — вдвое больше базовой доли. Значит, именно они несут информацию о классе.

Обратите внимание: код сравнивает доли, но не учитывает, сколько объектов попало в подвыборку «признак = 1». Если признак равен 1 у трёх объектов из тысячи, доля 0.5 может быть случайной. В настоящем дереве критерий устроен аккуратнее: он взвешивает примесь каждой ветви на её размер. Но логика «признак полезен, если меняет распределение метки» — та же.

Полезно связать это со стандартной мерой неопределённости — **примесью Джини**:

$$
G(p) = 1 - p^2 - (1-p)^2 = 2p(1-p).
$$

Для $p = 0.245$: $G = 2 \cdot 0.245 \cdot 0.755 \approx 0.370$. Для $p = 0.5$: $G = 0.5$ — максимум для двух классов, то есть подвыборка максимально «перемешана». Для $p = 1$: $G = 0$ — примеси нет. Кажется странным, что признак с долей 0.5 «лучше» базовой доли 0.245: но дерево смотрит не на то, насколько ветвь чище сама по себе, а на то, насколько она отличается от родителя. Ветвь с $p=0.5$ — это уже другой мир по сравнению с $p=0.245$; ветвь с $p=0.23$ — почти тот же самый.

Информационный выигрыш разбиения считается как уменьшение примеси:

$$
\Delta G = G(p_{\text{родитель}}) - \frac{n_L}{n}G(p_L) - \frac{n_R}{n}G(p_R),
$$

где $n_L$ и $n_R$ — размеры левой и правой ветвей. Дерево перебирает признаки и пороги и выбирает разбиение с максимальным $\Delta G$. В ноутбуке этот шаг не считается вручную, но именно он стоит за словами «признак сильнее всего меняет долю».

### 3. Второй уровень: признак, который не работал на всей выборке

После разбиения по признаку 2 код повторяет ту же процедуру внутри ветви, где признак 2 равен 1:

```python
Y1, X1 = Y[X[:, 2] == 1], X[X[:, 2] == 1]
print('после разбиения по признаку 2, p0:', round(float(Y1.mean()), 4))
for i in range(X1.shape[1]):
    print(f'  признак {i} == 1 -> доля {Y1[X1[:, i] == 1].mean():.4f}')
```

Вывод:

```text
после разбиения по признаку 2, p0: 0.5
  признак 0 == 1 -> доля 0.4977
  признак 1 == 1 -> доля 0.5167
  признак 2 == 1 -> доля 0.5000
  признак 3 == 1 -> доля 1.0000
  признак 4 == 1 -> доля 0.5081
```

Внутри ветви доля положительных выросла до 0.5. Признаки 0, 1, 2 и 4 почти не меняют картину: 0.4977, 0.5167, 0.5, 0.5081. А признак 3 даёт ровно 1.0: если в этой ветви признак 3 равен 1, объект гарантированно положительный. Это идеальное разбиение, примесь Джини в такой ветви равна нулю.

Отсюда видно, как работает рекурсия. На всей выборке признак 3 давал 0.496 — почти как признак 2, и дерево могло выбрать любой из них. Но после первого разбиения по признаку 2 именно признак 3 становится идеальным разделителем. Дерево не обязано выбирать «самый важный признак глобально»: оно выбирает лучшее разбиение **в текущем узле**, а не в целом по датасету.

Именно поэтому деревья хорошо ловят взаимодействия признаков: эффект признака 3 проявляется только в подвыборке, где признак 2 равен 1. Линейная модель с аддитивными вкладами такого взаимодействия не увидит без ручного добавления произведения признаков.

### 4. Обучение дерева на 100000 объектов

Третий файл — `unknown_data.dat.short`: 100000 строк, четыре числовых признака и метка. Данные читаются как `float`, потому что признаки уже не бинарные:

```python
from sklearn.tree import DecisionTreeClassifier, export_text

d = []
with open('files/unknown_data.dat.short') as f:
    for line in f:
        if line.strip():
            d.append([float(x) for x in line.split()])
d = np.array(d)
X, y = d[:, :-1], d[:, -1]

clf = DecisionTreeClassifier(random_state=0)
clf.fit(X, y)
print('точек:', len(y), '| признаков:', X.shape[1])
print('точность на обучающей выборке:', round(clf.score(X, y), 4))
print('важность признаков:', np.round(clf.feature_importances_, 3))
```

`random_state=0` фиксирует случайность: дерево само по себе детерминировано, но при равных выигрышах порядок признаков может зависеть от реализации, и фиксация делает результат воспроизводимым. `clf.score` для классификатора возвращает accuracy — долю правильных ответов. Вывод:

```text
точек: 100000 | признаков: 4
точность на обучающей выборке: 1.0
важность признаков: [0.602 0.307 0.017 0.074]
```

Точность `1.0` означает, что дерево без ограничения глубины идеально запомнило все 100000 объектов. Это не достижение, а тревожный сигнал: на новых данных такая модель почти наверняка ошибётся. Ограничения глубины и обрезка — тема следующего занятия; здесь важно зафиксировать симптом.

Важности признаков: 0.602, 0.307, 0.017, 0.074. Они нормированы так, что сумма равна 1:

$$
0.602 + 0.307 + 0.017 + 0.074 = 1.000.
$$

`feature_importances_` считается как суммарное уменьшение примеси, которое данный признак дал во всех узлах, где он использовался, делённое на общее уменьшение. Признак 0 вносит больше половины вклада, признак 1 — около трети, признаки 2 и 3 почти не используются. Но важность не говорит о направлении связи: она не показывает, растёт ли вероятность класса при увеличении признака. Для этого нужны частичные зависимости или сам текст дерева.

Важность также смещена в пользу признаков с большим числом уникальных значений: по ним можно подобрать много разных порогов, поэтому у дерева больше шансов «найти» хорошее разбиение даже на шуме. Поэтому по одной важности нельзя делать вывод «этот признак причинно важен»; это лишь мера использования в данной модели.

### 5. Как читать `export_text`

```python
print(export_text(clf, max_depth=3))
```

Вывод:

```text
|--- feature_0 <= 500.50
|   |--- class: 0.0
|--- feature_0 >  500.50
|   |--- feature_1 <= 300.50
|   |   |--- feature_3 <= 800.50
|   |   |   |--- class: 0.0
|   |   |--- feature_3 >  800.50
|   |   |   |--- feature_2 <= 150.50
|   |   |   |   |--- class: 0.0
|   |   |   |--- feature_2 >  150.50
|   |   |   |   |--- class: 1.0
|   |--- feature_1 >  300.50
|   |   |--- class: 1.0
```

Читается сверху вниз. Корень: если `feature_0 <= 500.50`, дерево сразу выдаёт класс 0. Иначе идёт вправо и проверяет `feature_1`. Если `feature_1 <= 300.50`, проверяется `feature_3`; если `feature_3 > 800.50`, то `feature_2`; при `feature_2 > 150.50` — класс 1. Если `feature_1 > 300.50` — класс 1 без дальнейших проверок.

Пороги вида `500.50`, `300.50`, `800.50`, `150.50` — это середины между соседними различными значениями признака. Если данные целые, граница между 500 и 501 записывается как 500.5. Такая запись позволяет однозначно сказать, куда попадёт значение 500 и куда 501.

`max_depth=3` ограничивает **вывод**, а не само дерево. Модель обучена без ограничения глубины и может иметь гораздо больше уровней; `export_text` просто не печатает их. Строки `|--- class: ...` — листья: в них дерево уже приняло решение. Если лист не чистый (в нём есть объекты разных классов), `export_text` может показать распределение, а классификатор выберет класс с наибольшей долей.

Обратите внимание, что дерево использует только три признака из четырёх на первых уровнях: `feature_0`, `feature_1`, `feature_3`, `feature_2`. Признак с важностью 0.017 всё-таки появился, но глубоко и редко; признак 3 с важностью 0.074 используется как уточняющая проверка. Это согласуется с важностями: чем больше вклад, тем ближе признак к корню и тем чаще он встречается.

Чтение дерева полезно ещё и для проверки здравого смысла. Если корень делит по признаку, который по смыслу не должен влиять на класс, стоит проверить данные: возможно, произошла утечка целевой переменной или признак является её производным. Дерево не понимает смысла, оно оптимизирует примесь.

## Код

Полный код ноутбука по ячейкам:

```python
import numpy as np
import matplotlib.pyplot as plt

# 1. Порог по кумулятивным распределениям

with open('files/classify_sdiff.dat', 'r') as f:
    for line in f:
        if not line.strip():
            continue
        a, b = line.split()
        j.append(int(a))
        s.append(int(b))
d1, d2 = np.array(j), np.array(s)

h1 = plt.hist(d1, density=True, cumulative=True, histtype='step',
              bins=range(-1000, 1000), label='класс 1')
h2 = plt.hist(d2, density=True, cumulative=-1, histtype='step',
              bins=range(-1000, 1000), label='класс 2')
plt.legend()
plt.title('Кумулятивные распределения двух классов')
plt.show()

a1, a2, c2 = np.array(h1[0]), np.array(h2[0]), np.array(h2[1])
idx = np.argmin(a1 + a2)
print('порог разделения:', c2[idx])

# 2. Информативность бинарных признаков
d = []
with open('files/binary_rules.dat') as f:
    for line in f:
        if line.strip():
            d.append([int(x) for x in line.split()])
d = np.array(d)

print('доля положительных (p0):', round(float(Y.mean()), 4))
for i in range(X.shape[1]):

Y1, X1 = Y[X[:, 2] == 1], X[X[:, 2] == 1]
print('после разбиения по признаку 2, p0:', round(float(Y1.mean()), 4))
for i in range(X1.shape[1]):
    print(f'  признак {i} == 1 -> доля {Y1[X1[:, i] == 1].mean():.4f}')

# 3. Дерево решений
from sklearn.tree import DecisionTreeClassifier, export_text

clf = DecisionTreeClassifier(random_state=0)
clf.fit(X, y)
print('точек:', len(y), '| признаков:', X.shape[1])
print('точность на обучающей выборке:', round(clf.score(X, y), 4))
print('важность признаков:', np.round(clf.feature_importances_, 3))

print(export_text(clf, max_depth=3))
```

### Что делает код

Первый блок читает два столбца целых чисел, строит накопленную гистограмму первого класса и обратную накопленную гистограмму второго, находит минимум их суммы и печатает соответствующую границу корзины. Второй блок читает бинарную таблицу, отделяет последний столбец как метку и печатает условные доли положительного класса сначала для всей выборки, затем для подвыборки после разбиения по признаку 2. Третий блок читает вещественную таблицу, обучает дерево без ограничений, печатает accuracy и важности, затем выводит первые три уровня структуры.

Параметр `max_depth` в `export_text` управляет только печатью; чтобы ограничить саму модель, его нужно передать в конструктор `DecisionTreeClassifier`. `random_state` фиксирует генератор, `feature_importances_` доступен только после `fit`.

## Формулы

| Величина | Формула | Смысл |
| --- | --- | --- |
| Доля класса | $p = \frac{1}{n}\sum_i y_i$ | Вероятность положительного класса; при $p_0=0.245$ «всегда 0» даёт accuracy 0.755 |
| Примесь Джини | $G(p) = 2p(1-p)$ | 0 при чистом узле, 0.5 при равном смешении двух классов |
| Выигрыш разбиения | $\Delta G = G(p) - \frac{n_L}{n}G(p_L) - \frac{n_R}{n}G(p_R)$ | Насколько разбиение уменьшает неопределённость |
| Сумма ошибок порога | $E(t) = F_1(t) + P_2(X > t)$ | Минимум задаёт порог между двумя классами |
| Accuracy | $\text{acc} = \frac{1}{n}\sum_i [\hat{y}_i = y_i]$ | Доля правильных ответов; на обучающей выборке здесь 1.0 |

## Задание / практика

Нужно было пройти три шага.

1. **Найти порог.** По файлу `classify_sdiff.dat` построить кумулятивные распределения двух классов, найти точку минимума суммы и получить порог. Результат — `107.0`.
2. **Оценить признаки.** По файлу `binary_rules.dat` посчитать базовую долю положительного класса и условные доли при каждом признаке, равном 1. Найти признаки, которые сильнее всего меняют долю, затем повторить расчёт внутри ветви после разбиения по признаку 2. Результат — признаки 2 и 3 как информативные, признак 3 как идеальный разделитель внутри ветви.
3. **Обучить дерево.** По файлу `unknown_data.dat.short` обучить `DecisionTreeClassifier`, получить accuracy на обучающей выборке, важности признаков и текстовое представление первых уровней. Результат — accuracy `1.0`, важности `[0.602, 0.307, 0.017, 0.074]`, корень по `feature_0` с порогом `500.50`.

Результат считается достигнутым, если вы можете объяснить, почему порог оказался именно таким, почему дерево выбрало признак 0 корневым и что означает accuracy `1.0` на обучающей выборке.

## Что спросят

**Как ищется порог между двумя классами?**
По кумулятивным распределениям: для каждого порога складываются доля ошибок слева и доля ошибок справа, выбирается минимум суммы. В ноутбуке это `np.argmin(a1 + a2)`, результат — 107.0.

**Почему для второго класса используется `cumulative=-1`?**
Чтобы получить долю объектов со значением больше порога. Тогда обе кривые можно сложить и искать минимум; обычная функция распределения росла бы в другую сторону.

**Что такое базовая доля и зачем она нужна?**
Это доля положительного класса на всей выборке, здесь 0.245. Она задаёт ориентир: «всегда 0» даёт accuracy 0.755, и модель должна быть лучше этого.

**Почему дерево выбрало признак 2, хотя признак 3 даёт почти такую же долю?**
На 전체 выборке их доли близки (0.500 и 0.496), но после разбиения по признаку 2 признак 3 даёт 1.0. Дерево выбирает лучшее разбиение в текущем узле, а не самый важный признак глобально.

**Что означает `feature_importances_` и почему сумма равна 1?**
Это нормированный суммарный вклад признака в уменьшение примеси во всех узлах. sklearn делит вклады на общее уменьшение, поэтому сумма важностей равна единице.

**Почему accuracy на обучающей выборке равна 1.0?**
Дерево без ограничения глубины растёт, пока каждый лист не станет чистым, то есть пока оно не запомнит обучающую выборку. Это признак переобучения, а не хорошего качества.

**Как читать `feature_0 <= 500.50`?**
Значения меньше либо равны 500.5 идут в левую ветвь, больше — в правую. Порог 500.5 — середина между соседними значениями 500 и 501.

**Ограничивает ли `max_depth=3` в `export_text` глубину модели?**
Нет, только глубину печати. Сама модель обучена без ограничений; чтобы ограничить её, `max_depth` передают в `DecisionTreeClassifier`.
