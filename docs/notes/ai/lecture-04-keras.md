# TensorFlow и Keras: первая нейронная сеть

## О чём эта запись

Занятие посвящено переходу от классических моделей к нейронным сетям. Сначала сравниваются две библиотеки — TensorFlow и PyTorch: чем они отличаются по философии и почему в курсе выбран TensorFlow. Потом на игрушечной регрессии собирается первая сеть из одного нейрона: входной слой, полносвязный слой `Dense`, компиляция, обучение по эпохам и графики лосса. На этой же задаче вводятся валидационная выборка и ранняя остановка. Вторая половина занятия — классификация по файлу `files/res_oval.dat`: один нейрон с сигмоидой, затем сеть со скрытыми слоями и ReLU, а в конце — честная оценка через `classification_report`, дисбаланс классов и матрицу ошибок.

## Главные идеи

- TensorFlow сам распределяет вычисления по доступному железу (CPU, GPU, память), а в PyTorch это делает программист. За это PyTorch платит более громоздким кодом на простых задачах, но выигрывает на сложных архитектурах.
- В Keras три уровня API: `Sequential` (стопка слоёв), Functional (произвольный граф) и Subclassing (свой класс). В курсе используется первый.
- Нейрон считает $f(w\cdot x+b)$. Сеть состоит из входного, скрытых и выходного слоёв; входной слой определяется данными.
- `Dense` — полносвязный слой: каждый нейрон получает все выходы предыдущего слоя. Для регрессии на выходе `linear`, для двух классов — `sigmoid`, для многих — `softmax`.
- `compile` инициализирует веса и задаёт оптимизатор, лосс и метрики; `fit` учит по эпохам. Эпоха — один полный прогон по данным.
- У лосса нет содержательного смысла: важно, чтобы он падал. Для остановки в нужный момент используют `validation_split` и `EarlyStopping` с `patience`.
- Скрытые слои обязаны иметь нелинейную активацию. Два линейных слоя подряд сворачиваются в один линейный — сеть не становится умнее.
- При дисбалансе классов accuracy обманывает. Рабочие метрики — F1, macro F1 и AUC PR; матрица ошибок показывает, какой класс модель путает.

## Полный разбор

### 1. TensorFlow и PyTorch: две философии

Для нейронных сетей есть две основные библиотеки. Первая — TensorFlow, вторая — PyTorch.

**TensorFlow** сам понимает, на каком железе работает, и старается оптимизировать программу под него: что держать в оперативной памяти, что считать на CPU, что отправить на GPU. Для учебных задач это удобно: один и тот же код запускается на ноутбуке и на машине с видеокартой, не требуя ручной настройки.

**PyTorch** — стандарт де-факто в индустрии, на нём пишут многие крупные компании. Но распределение вычислений по железу там полностью на программисте: нужно самому решать, какие тензоры держать в памяти, что считать на CPU, а что отправлять на GPU. У PyTorch фактически один уровень сложности — сразу тяжёлый. Простые задачи описываются громоздко, зато сложные архитектуры делать легче, чем на TensorFlow. PyTorch в курсе не изучается, он остаётся на следующие семестры.

Отсюда практическое правило: для быстрого прототипа и учебной задачи TensorFlow компактнее; для нестандартной архитектуры с ручным контролем вычислений удобнее PyTorch. В этом семестре весь код будет на TensorFlow.

### 2. Три уровня API Keras

`tf.keras` даёт три уровня сложности. В курсе используется первый, но знать остальные полезно, чтобы понимать границы инструмента.

| Уровень | Что это | Когда нужен |
|---|---|---|
| **Sequential** | модель — стопка слоёв, которые добавляются через `model.add(...)` | большинство задач; с него начинают |
| **Functional API** | слои соединяются в произвольный граф через `tf.keras.Model(inputs=..., outputs=...)` | сложные архитектуры: ветвления, несколько входов и выходов; обучаются так же легко |
| **Subclassing** | свой класс — наследник `tf.keras.Model` с собственным методом `call` | произвольные операции над сетью и её обучением; фактически уровень PyTorch |

Третий уровень самый мощный: он позволяет делать с сетью что угодно, но и требует понимания её внутреннего устройства. Если задача доросла до Subclassing, TensorFlow перестаёт быть удобным инструментом и логичнее перейти на PyTorch. Поэтому Subclassing в курсе не разбирается.

### 3. Нейрон, слои и `Input`

Простейшая нейронная сеть начинается с одного нейрона. Нейрон принимает вход $x$, умножает его на вес $w$, прибавляет смещение $b$ и пропускает результат через функцию активации $f$:

$$y=f(w\cdot x+b).$$

Сеть состоит из трёх частей:

1. **входной слой** — определяет, какой формы данные приходят;
2. **скрытые слои** — промежуточные преобразования;
3. **выходной слой** — то, что нам нужно получить.

В Keras модель `Sequential` собирается по шагам. Входной слой задаётся так:

```python
model.add(tf.keras.layers.Input(shape=(1,)))
```

Запись `shape=(1,)` означает: на вход приходит вектор из одного числа. Запятая внутри скобок обязательна, потому что `shape` — это кортеж; без неё Python поймёт `(1)` как просто число в скобках. Для двумерных данных было бы `shape=(2,)`.

Следующий слой — полносвязный. В TensorFlow ему соответствует `Dense` (дословно «плотный»), он же Fully Connected. В нём указывают число нейронов и функцию активации. Каждый нейрон такого слоя получает все выходы предыдущего слоя, поэтому число связей быстро растёт.

Для регрессии выходной слой не должен ничего сжимать или ограничивать, поэтому активация `linear`. Это важно: правило относится только к выходному слою, скрытые слои могут иметь любые активации.

### 4. Первая модель: регрессия

Задача — восстановить зависимость

$$y=5{,}1x+3+\varepsilon,$$

где $\varepsilon$ — небольшой шум. Нужно найти «волшебные коэффициенты» 5.1 и 3 по данным. Датасет создаётся случайно, чтобы модель не могла просто выучить таблицу.

Модель из одного нейрона:

```python
model = tf.keras.models.Sequential()
model.add(tf.keras.layers.Input(shape=(1,)))
model.add(tf.keras.layers.Dense(1, activation='linear'))
print(model.summary())
```

`summary()` печатает таблицу слоёв. В ней важны три итоговые строки:

- **Total params** — сколько параметров в модели всего;
- **Trainable params** — сколько из них обучаются;
- **Non-trainable params** — сколько заморожено.

У одного нейрона на одномерном входе ровно два параметра: вес и смещение. Каждый параметр по умолчанию имеет тип `float32` и занимает 4 байта, поэтому в таблице будет 8 байт. Любой слой или параметр можно пометить как необучаемый (`trainable=False`) — тогда оптимизатор его не меняет. Иногда это полезно: например, когда часть сети уже обучена и её хотят заморозить.

### 5. `compile` и `fit`: как сеть учится

После сборки модель нужно скомпилировать:

```python
model.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=1e-1),
              loss='mse')
```

`compile` не только задаёт настройки, но и инициализирует веса случайными числами. До этого вызова модель ещё не готова к обучению.

Параметры `compile`:

- **optimizer** — алгоритм, который ищет минимум функции потерь; `Adam` — стандартный выбор;
- **loss** — что именно минимизировать; для регрессии это `mse` (mean squared error, средний квадрат ошибки);
- **metrics** — что дополнительно печатать в логе; на качество обучения не влияет.

Обучение запускается методом `fit`:

```python
history = model.fit(x, y, epochs=300, validation_split=0.2)
```

**Эпоха** — один полный прогон по всему обучающему датасету. За 300 эпох сеть 300 раз увидит все объекты. `fit` возвращает объект `history`, в котором лежат значения лосса и метрик по эпохам:

```python
plt.plot(history.history['loss'], label='loss@train')
plt.plot(history.history['val_loss'], label='loss@val')
plt.legend()
```

Смысл лосса: у него нет физической интерпретации, это внутренняя величина оптимизации. Единственное, что важно, — в процессе обучения она должна **уменьшаться**. Если падает, всё идёт нормально. Если растёт или стоит на месте, что-то не так: слишком большой шаг обучения, неправильная функция потерь или ошибка в данных.

### 6. Переобучение, `validation_split` и `EarlyStopping`

Если учить сеть слишком долго, она переобучится: на обучающих данных лосс будет маленьким, а на новых — большим. Типичная картина: кривая `loss` монотонно падает, а `val_loss` сначала падает, потом достигает минимума и начинает расти. Минимум `val_loss` — момент, когда пора останавливаться.

Проблема в том, что тестовую выборку при обучении смотреть нельзя. Решение — выделить из обучающих данных валидационную часть:

```python
es = tf.keras.callbacks.EarlyStopping(patience=5, mode='min',
                                      monitor='val_loss')
history = model.fit(x, y, validation_split=0.2,
                    epochs=1000, callbacks=[es])
```

`validation_split=0.2` означает: TensorFlow случайно отдаст 20% данных под валидацию. На оставшихся 80% он будет искать параметры, а на 20% — только считать лосс `val_loss`. По этой части модель не учится.

Чтобы не гадать, на какой эпохе остановиться, используют **раннюю остановку**. Параметры `EarlyStopping`:

- **monitor** — за какой величиной следить; здесь `val_loss`;
- **mode='min'** — искать минимум; для лосса это всегда минимум, для метрик может быть максимум;
- **patience=5** — сколько ещё эпох подождать после найденного минимума, прежде чем остановиться.

Зачем нужен `patience`: минимум нельзя распознать в момент, когда он достигнут. Нужно пройти несколько эпох вперёд и убедиться, что лучше не стало. Если за 5 эпох улучшения нет, обучение прекращается. Без этого сеть будет учиться все отведённые эпохи до конца, даже когда качество уже не растёт.

Callback передаётся в `fit` списком `callbacks=[es]` и вызывается в конце каждой эпохи. Эпох задают с запасом (например, 1000): ранняя остановка всё равно завершит обучение раньше. Если поставить ровно столько эпох, сколько нужно, сеть может не успеть дойти до минимума.

В демонстрации используется `Adam` с шагом `learning_rate=1e-1` (в тексте лекции называется `1e-2`; оба варианта больше стандартного `1e-3`). Больший шаг позволяет быстрее добраться до минимума на такой простой задаче. На сложных сетях слишком большой шаг, наоборот, приводит к расходимости.

### 7. Схема модели и зачем `pydot`

Полезная функция — `tf.keras.utils.plot_model`:

```python
tf.keras.utils.plot_model(model, show_layer_activations=True,
                          show_shapes=True, to_file='model.png')
```

Она рисует схему сети: слои, их активации, размерности входов и выходов. Чтобы это работало, нужен Python-пакет `pydot` и установленный в системе Graphviz. Без `pydot` функция падает с `ImportError` — в сохранённом ноутбуке это видно до установки пакета.

На схеме первой регрессионной модели видно: на входе `(None, 1)`, на выходе `(None, 1)`. `None` означает произвольное число объектов — оно появляется потому, что размер батча заранее неизвестен. Единица — размерность одного объекта.

В PyTorch такой наглядной схемы почти нет: архитектуру приходится понимать по коду. В TensorFlow это одно из практических преимуществ.

### 8. Тип задачи определяет выходной слой

Перед классификацией повторяется таблица типов задач:

| Что предсказываем | С учителем | Без учителя |
|---|---|---|
| числовую величину | **регрессия** | аппроксимация |
| категорию (класс) | **классификация** | кластеризация |

От задачи зависит выходной слой и функция потерь:

- **регрессия** — один нейрон с `linear`, лосс `mse` (реже `mae`);
- **классификация на два класса** — один нейрон с `sigmoid`, лосс `binary_crossentropy`;
- **классификация на несколько классов** — `softmax` и по нейрону на класс, категориальная кросс-энтропия.

Сигмоида сжимает любое число в интервал от 0 до 1, поэтому её выход можно интерпретировать как вероятность первого класса. Порог 0.5 превращает вероятность в метку: больше — класс 1, меньше или равно — класс 0.

### 9. Классификация `files/res_oval.dat`: один нейрон

В файле три колонки: первые две — координаты точки, последняя — метка класса. Данные загружаются, первые два столбца становятся признаками `x`, третий — меткой `y`. Сразу выполняется `train_test_split`: обучающая и тестовая части.

Сначала собирается учебная модель из одного нейрона:

```python
model.add(tf.keras.layers.Input(shape=(2,)))
model.add(tf.keras.layers.Dense(1, activation='sigmoid'))
```

Один нейрон с сигмоидой проводит **одну разделяющую поверхность**. В двумерном пространстве это прямая: по одну сторону вероятность близка к нулю, по другую — к единице, а между ними есть переходная зона, где модель не может определиться. На картинке это выглядит как полоса с плавным изменением цвета.

Такая модель работает ожидаемо, но часто недостаточно: если классы расположены «вложенно» или по разные стороны кривой, одной прямой их не разделить. Ошибка не случайна — она означает, что модель слишком простая. Один нейрон физически не может провести две границы.

### 10. Скрытые слои и обязательная нелинейность

Чтобы разделить сложные данные, добавляют скрытые слои. Сначала в лекции обсуждается, сколько нейронов взять: для двумерной задачи берут с запасом, в коде — 8 и 10 нейронов.

Ключевой момент — активация. Если поставить в скрытые слои `linear`, сеть не станет сложнее. Один линейный нейрон считает $Ax+B$. Два подряд:

$$y=C(Ax+D)+E=CA\,x+(CD+E).$$

Это снова линейная функция, только с другими коэффициентами. Сколько линейных слоёв ни добавь, всё свернётся в один. Поэтому добавление слоёв без нелинейности не повышает качество — это бессмысленная конструкция.

Нужна нелинейная активация. В коде используется **ReLU**:

$$\mathrm{ReLU}(x)=\max(0,x).$$

Слева от нуля она равна нулю, справа повторяет значение. Благодаря излому в нуле композиция слоёв перестаёт быть линейной, и сеть может приближать сложные границы.

У ReLU есть особенность: часть нейронов может «замолчать» — если вход всегда отрицательный, выход всегда нулевой, и градиент через такой нейрон не идёт. Поэтому нейронов берут с запасом: в коде оценку умножают на 2 (`4*2` и `5*2`). Это не строгая формула, а практическое правило компенсации «мёртвых» нейронов.

Итоговая архитектура:

```python
model.add(tf.keras.layers.Input(shape=(2,)))
model.add(tf.keras.layers.Dense(4*2, activation='relu'))
model.add(tf.keras.layers.Dense(5*2, activation='relu'))
model.add(tf.keras.layers.Dense(1, activation='sigmoid'))
```

На входе два числа, первый скрытый слой даёт 8 выходов, второй — 10, последний нейрон считает вероятность. Схема `plot_model` показывает эти размерности явно.

### 11. Компиляция классификатора и метрики

```python
model.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=1e-2),
    loss='binary_crossentropy',
    metrics=['accuracy',
             tf.keras.metrics.AUC(curve='PR', name='aurpc')])
```

Для двух классов функция потерь — `binary_crossentropy`. Она штрафует за уверенный неправильный ответ сильнее, чем за неуверенный, и хорошо сочетается с сигмоидой.

В `metrics` перечислено, что печатать в логе:

- `accuracy` — доля правильных ответов;
- `AUC(curve='PR')` — площадь под кривой precision–recall. Имя `aurpc` задано вручную, чтобы в логе было понятное название.

Зачем AUC PR, если есть accuracy? Из-за дисбаланса. Если объектов одного класса в полтора-два раза больше, accuracy может быть высокой у бесполезной модели, которая всегда отвечает «больший класс». AUC PR показывает качество ранжирования вероятностей: насколько хорошо модель отделяет классы при разных порогах.

### 12. Дисбаланс и отчёт по классам

После обучения `model.predict(xtest)` возвращает **вероятности**, а не метки. Их нужно перевести в классы порогом 0.5:

```python
ypc = yp
ypc[yp > 0.5] = 1
ypc[yp <= 0.5] = 0
```

Затем строится `classification_report`. В прогоне на занятии support получился примерно 1700 объектов одного класса против 721 другого — отношение больше 1.5. Это и есть дисбаланс.

Числа из лекции: accuracy на валидации около 95.5%, AUC PR около 0.98, macro F1 около 0.94. Accuracy выглядит отлично, но по support видно, что датасет разбалансирован, поэтому доверять ей нельзя. Macro F1 и AUC PR дают более честную картину, при этом один класс всё равно определяется хуже другого.

Про порог дисбаланса в записи есть расхождение: на этом занятии называется отношение 1.5:1, на предыдущем — около 3:1. Единого числа нет; важно, что при заметном перекосе accuracy перестаёт быть показателем качества.

**Матрица ошибок** строится одной строкой:

```python
print(confusion_matrix(ytest, ypc))
```

Строки — истинные классы, столбцы — предсказанные, диагональ — правильные ответы. Из неё видно, какой класс «утекает» в другой. Precision отвечает на вопрос «какая доля названных классом действительно этого класса», recall — «какую долю класса модель нашла». Если precision и recall сильно расходятся, модель смещена в сторону одного класса.

### 13. Полный пайплайн

Порядок работы, который повторяется на всех занятиях:

1. получить данные и сразу разделить их на обучающую и тестовую части;
2. всё обучение вести только на обучающей части, валидацию при необходимости выделять из неё;
3. предсказывать и считать метрики только на тестовой части;
4. метрики выбирать по задаче: для регрессии — `mse`, для классификации — F1, macro F1, матрица ошибок; accuracy смотреть только на сбалансированных данных.

Главная мысль: модель должна работать не на обучающих данных, а на новых. Высокий `score` на обучении — не достижение, а часто признак переобучения.

## Код

Рабочая классификация из ноутбука (первые строки — остаток регрессионного примера, затем `x` и `y` перезаписываются данными из файла):

```python
import tensorflow as tf
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split

d = []
f = open('files/res_oval.dat')
for s in f:
    d.append([float(x) for x in s.split()])

d = np.array(d)
N = 1000
x = np.random.rand(N)
y = 5.1 * x + 3 + np.random.rand(N) * 0.5

x = d[:, :2]
y = d[:, 2]
xtr, xtest, ytr, ytest = train_test_split(x, y)

model = tf.keras.models.Sequential()
model.add(tf.keras.layers.Input(shape=(2,)))
model.add(tf.keras.layers.Dense(4*2, activation='relu'))
model.add(tf.keras.layers.Dense(5*2, activation='relu'))
model.add(tf.keras.layers.Dense(1, activation='sigmoid'))

model.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=1e-2),
    loss='binary_crossentropy',
    metrics=['accuracy',
             tf.keras.metrics.AUC(curve='PR', name='aurpc')])
es = tf.keras.callbacks.EarlyStopping(patience=5, mode='min',
                                      monitor='val_loss')
history = model.fit(xtr, ytr, validation_split=0.2,
                    epochs=1000, callbacks=[es])

plt.plot(history.history['loss'], label='l@train')
plt.plot(history.history['val_loss'], label='l@val')
plt.legend()

yp = model.predict(xtest)
tf.keras.utils.plot_model(model, show_layer_activations=True,
                          show_shapes=True)
```

Перевод вероятностей в классы и отчёт:

```python
from sklearn.metrics import classification_report, confusion_matrix

ypc = yp
ypc[yp > 0.5] = 1
ypc[yp <= 0.5] = 0
print(classification_report(ytest, ypc))
print(confusion_matrix(ytest, ypc))
```

Регрессионный черновик из ноутбука — в исправленном виде (в исходной ячейке опечатки `tf.keras.model`, `tf.kerass`, `opptimizer`, `le-1`, `callback`; шум задан одним числом `np.random.rand()`, здесь — вектором длины `N`, чтобы разброс был у каждой точки):

```python
N = 1000
x = np.random.rand(N)
y = 5.1 * x + 3 + np.random.rand(N) * 0.5

model = tf.keras.models.Sequential()
model.add(tf.keras.layers.Input(shape=(1,)))
model.add(tf.keras.layers.Dense(1, activation='linear'))
print(model.summary())

model.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=1e-1),
              loss='mse')
es = tf.keras.callbacks.EarlyStopping(patience=5, mode='min',
                                      monitor='val_loss')
history = model.fit(x, y, validation_split=0.2,
                    epochs=300, callbacks=[es])

plt.plot(history.history['loss'], label='l@train')
plt.plot(history.history['val_loss'], label='l@val')
plt.legend()

yp = model.predict(x)
tf.keras.utils.plot_model(model, show_layer_activations=True,
                          show_shapes=True)
plt.scatter(x, y)
plt.scatter(x, yp)
```

### Что делает код

**Загрузка.** Файл читается построчно, каждая строка разбивается по пробелам и превращается в список чисел. Из списка получается матрица `d`. `d[:, :2]` берёт первые два столбца — признаки, `d[:, 2]` — третий столбец, метку. `train_test_split` делит пары `x`/`y` согласованно: объект и его метка остаются в одной части.

**Модель.** `Sequential()` создаёт пустой контейнер. `Input(shape=(2,))` объявляет вход. Два `Dense` с `relu` — скрытые слои, последний `Dense(1, activation='sigmoid')` — выход: одно число от 0 до 1. Веса инициализируются в `compile`.

**Обучение.** `compile` задаёт `Adam`, `binary_crossentropy` и две метрики. `EarlyStopping` следит за `val_loss`, ищет минимум и терпит 5 эпох без улучшений. `fit` делит `xtr`/`ytr` на 80/20, учится и возвращает историю. По `history.history['loss']` и `['val_loss']` строятся две кривые: их расхождение — признак переобучения.

**Предсказание.** `predict(xtest)` возвращает вероятности формы `(n, 1)`. Маска `yp > 0.5` заменяет значения на 1, вторая маска — на 0. `classification_report` печатает precision, recall, F1 и support по классам, `confusion_matrix` — матрицу ошибок.

**Регрессия.** Один нейрон с `linear` учится зависимости $y=wx+b$. После обучения `w` и `b` лежат в весах слоя; их можно достать через `model.layers[0].get_weights()`. `predict(x)` даёт предсказания, которые накладываются на исходные точки.

## Формулы

| Величина | Формула | Смысл |
|---|---|---|
| Нейрон | $y=f(w\cdot x+b)$ | взвешенная сумма входов плюс смещение, затем активация |
| Линейный слой | $y=wx+b$ | частный случай без нелинейности; используется на выходе регрессии |
| ReLU | $\max(0,x)$ | ноль слева, значение справа; даёт нелинейность |
| Сигмоида | $\sigma(z)=\dfrac{1}{1+e^{-z}}$ | сжимает число в интервал (0, 1), трактуется как вероятность |
| Свёртка двух линейных слоёв | $C(Ax+D)+E=CA\,x+(CD+E)$ | показывает, что без нелинейности слои эквивалентны одному |
| MSE | $\dfrac{1}{n}\sum_i(y_i-\hat y_i)^2$ | средний квадрат ошибки для регрессии |
| Precision | $\dfrac{TP}{TP+FP}$ | доля верных среди названных положительными |
| Recall | $\dfrac{TP}{TP+FN}$ | доля найденных среди всех реальных положительных |
| F1 | $\dfrac{2PR}{P+R}$ | гармоническое среднее precision и recall |

## Что спросят

**Чем TensorFlow отличается от PyTorch?**
TensorFlow сам распределяет вычисления по CPU/GPU и памяти, код проще переносить между машинами. В PyTorch распределением управляет программист; простые задачи описываются громоздко, зато сложные архитектуры удобнее.

**Какие три уровня API есть в Keras?**
`Sequential` — стопка слоёв; Functional — произвольный граф с несколькими входами и выходами; Subclassing — свой класс с методом `call`, уровень PyTorch. В курсе используется `Sequential`.

**Что делает `Dense`?**
Полносвязный слой: каждый нейрон получает все выходы предыдущего слоя, умножает на веса, прибавляет смещение и применяет активацию.

**Почему для регрессии на выходе `linear`, а для двух классов — `sigmoid`?**
Регрессия предсказывает любое число, поэтому выход не ограничивают. Для двух классов нужно получить вероятность от 0 до 1, её даёт сигмоида; порог 0.5 превращает вероятность в метку.

**Что делает `compile` и что — `fit`?**
`compile` задаёт оптимизатор, лосс, метрики и инициализирует веса. `fit` обучает модель: прогоняет данные заданное число эпох, считает лосс и обновляет веса.

**Что такое эпоха?**
Один полный проход по всему обучающему датасету.

**Зачем нужны `validation_split` и `EarlyStopping`?**
`validation_split` выделяет часть обучающих данных для контроля переобучения. `EarlyStopping` следит за `val_loss` и останавливает обучение, когда улучшений нет `patience` эпох.

**Почему скрытые слои не могут быть линейными?**
Композиция линейных преобразований снова линейна, поэтому несколько линейных слоёв эквивалентны одному. Без нелинейности добавление слоёв не увеличивает выразительность сети.

**Почему accuracy плоха при дисбалансе?**
Ответ «всегда больший класс» даёт высокую долю правильных ответов, но меньший класс полностью игнорируется. Нужны precision, recall, F1, macro F1 и матрица ошибок.

**Что показывает матрица ошибок?**
Строки — истинные классы, столбцы — предсказанные. Диагональ — правильные ответы, вне диагонали — ошибки; по матрице видно, какие классы модель путает.

## Связи

- **С предыдущей темой:** деревья, SVM и логистическая регрессия тоже строят разделяющую поверхность. Нейросеть обобщает эту идею: поверхность собирается из многих нейронов и обучается градиентным спуском.
- **С анализом данных:** `train_test_split`, `validation_split`, `classification_report` и `confusion_matrix` — те же инструменты, что в классических моделях; меняется только сама модель.
- **С практикой:** в `practice-6` линейная регрессия собирается как один нейрон с `linear` — это прямой мост между МНК и TensorFlow.
- **В домашках:** полный пайплайн (split → fit → predict → метрики) и проверка дисбаланса по support понадобятся в любой задаче классификации.
