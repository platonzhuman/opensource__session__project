# 3. Транзакция 1: структура таблиц и счётчики

Первая транзакция создаёт таблицы и счётчики (`sequence`) для авто-генерации `id`.

!!! abstract "Цель урока"
    Ты создашь структуру своих таблиц со счётчиками внутри первого блока.

## Шаг 1 · Создаём таблицу

Твоя схема состоит из таблиц-справочников и таблиц-данных:

| Таблица | Что хранит |
| --- | --- |
| `positions` | должности |
| `eq_types` | оборудование (`ДМК`, `ВР`) |
| `users` | сотрудники |
| `packs` | пачки измерений |
| `parametrs` | измерения |
| `base_units` | физические величины |
| `units` | единицы измерения |
| `parameter_types` | параметры |

```sql
do $$
begin
	create table positions(
		id integer primary key,
		name varchar(150) not null
	);
	-- остальные таблицы так же
end $$;
```

!!! question "Сделай"
    Почему `create table` пишется внутри `begin … end`?

??? success "Проверить"
    Это тело блока — команды выполняются при запуске блока. Код между `begin`
    и `end`.

## Шаг 2 · Счётчик `sequence`

`id` должен расти сам. Для этого есть **счётчик**:

```sql
create sequence seq_positions;
alter table positions alter column id
	set default nextval('seq_positions');
```

- `create sequence` — создаёт генератор чисел;
- `set default nextval(...)` — связывает его с колонкой `id`.

Теперь `id` при вставке можно не указывать.

!!! question "Сделай"
    Что делает `nextval('seq_positions')`?

??? success "Проверить"
    Возвращает следующее число счётчика: 1, 2, 3 … Оно подставляется в `id`.

## Шаг 3 · Сколько счётчиков

Счётчик нужен **каждой** таблице, у которой есть `id`. Итого по одному на каждую
из твоих таблиц: `seq_positions`, `seq_eq_types`, `seq_users`, `seq_packs`,
`seq_parametrs`, `seq_base_units`, `seq_units`, `seq_parameter_types`.

!!! question "Сделай"
    Сколько счётчиков создаст первая транзакция?

??? success "Проверить"
    Восемь — по одному на каждую таблицу с колонкой `id`.

## Шаг 4 · Оформляем первую транзакцию

Транзакция 1 = `begin;` + блок с созданием таблиц и счётчиков + `commit;`.

```sql
begin;

do $$
begin
	create table positions(...);
	create sequence seq_positions;
	alter table positions alter column id set default nextval('seq_positions');
	-- и так для всех таблиц
end $$;

commit;
```

!!! question "Сделай"
    Где здесь сама транзакция, а где — блок?

??? success "Проверить"
    Транзакция — это `begin; … commit;`. Блок `do $$ … $$` — её содержимое.

!!! tip "Правило"
    Первая транзакция: `begin;` → `do $$` со всеми `create table` и `create
    sequence` → `commit;`. Никаких данных и связей здесь ещё нет.

## Откуда числа

Восемь таблиц и восемь счётчиков — из твоей схемы из прошлых домашек. Таблица
температуры (Таблица 1) добавляется в уроке 7.

## Наивные вопросы

!!! question "Зачем счётчику отдельное имя?"
    Чтобы не путаться: `seq_<таблица>` — понятно, к какой таблице он относится.

!!! question "Что если запустить блок второй раз?"
    `create table` упадёт («таблица уже существует»). Поэтому скрипт и рассчитан
    на чистую базу — как первый скрипт миграции.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** какой `id` получит первая строка в `positions`?
    2. **Объясни**, зачем `set default nextval(...)`.
    3. **Напиши** создание счётчика для `users`.

??? success "Проверить"
    1. `1`.
    2. Чтобы `id` подставлялся автоматически и был уникальным.
    3. `create sequence seq_users;` и `alter table users alter column id set default nextval('seq_users');`
