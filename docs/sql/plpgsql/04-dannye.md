# 4. Транзакция 2: тестовые данные

Вторая транзакция наполняет таблицы данными. `id` теперь подставляет счётчик.

!!! abstract "Цель урока"
    Ты научишься вставлять данные, не указывая `id`, и оформишь вторую транзакцию.

## Шаг 1 · Вставка без `id`

Так как у колонки `id` есть `default nextval(...)`, указывать её не нужно:

```sql
insert into positions (name) values
	('оператор метеопоста'),
	('начальник метепоста'),
	('техник');
```

Счётчик сам выдаст `id` = 1, 2, 3.

!!! question "Сделай"
    Почему `id` не указан?

??? success "Проверить"
    У колонки есть значение по умолчанию — `nextval('seq_positions')`. Оно
    подставит следующее число.

## Шаг 2 · Данные из ТЗ

Данные в домашке берём из ТЗ: оборудование `ДМК`/`ВР`, параметры, единицы. Например:

```sql
insert into eq_types (name) values ('ДМК'), ('ВР');

insert into users (full_name, position_id) values
	('Иванов Иван', 1),
	('Петров Пётр', 2);
```

!!! question "Сделай"
    Что означает `position_id = 1` в строке сотрудника?

??? success "Проверить"
    Ссылку на должность с `id = 1` (оператор метеопоста). Это связь, но саму
    связь-ограничение мы навесим позже — в транзакции 3.

## Шаг 3 · Таблицы-данные

Пачки и измерения — тоже обычные вставки:

```sql
insert into packs (user_id, eq_type_id, created_on) values
	(1, 1, date '2026-09-01');

insert into parametrs (pack_id, parameter_type_id, value) values
	(1, 1, 100),
	(1, 2, 15);
```

!!! question "Сделай"
    Почему здесь `user_id = 1`, а `id` пачки не указан?

??? success "Проверить"
    `id` пачки подставит счётчик. А `user_id = 1` — это код сотрудника, на
    которого ссылается пачка.

## Шаг 4 · Оформляем вторую транзакцию

Вторая транзакция повторяет каркас первой: `begin;` → `do $$` с `insert` → `commit;`.

```sql
begin;

do $$ begin
	insert into positions (name) values ('оператор метеопоста');
	-- и так далее
end $$;

commit;
```

!!! question "Сделай"
    Чем содержимое этого блока отличается от предыдущего?

??? success "Проверить"
    Раньше были `create table`/`create sequence`, теперь — только `insert`.

!!! tip "Правило"
    Вторая транзакция = только `insert`. Данные можно сгенерировать и через ИИ —
    как в третьей домашке, промт приложить в PR.

## Откуда числа

Параметров и единиц столько, сколько в ТЗ. `position_id`, `user_id`, `pack_id`,
`parameter_type_id` — коды из уже вставленных таблиц.

## Наивные вопросы

!!! question "Почему данные во второй транзакции, а не в первой?"
    Сначала структура (таблицы должны существовать), только потом данные. Это
    и есть смысл трёх отдельных транзакций.

!!! question "Что если ошибиться в данных?"
    Транзакция откатится, база останется чистой — ограничения из третьей
    транзакции ещё не навешены, поэтому явных ошибок связей не будет.
