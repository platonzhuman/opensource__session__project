# 7. ER-диаграмма и таблица температуры

Две последние части: визуальная ER-диаграмма и новая таблица расчёта температуры.

!!! abstract "Цель урока"
    Ты построишь ER-диаграмму в pgAdmin и добавишь таблицу расчёта температуры
    (Таблица 1 из ТЗ) вместе с данными.

## Шаг 1 · Что такое ER-диаграмма

!!! note "Определение"
    **ER-диаграмма** (Entity-Relationship) — рисунок таблиц и связей между ними.
    Прямоугольники — таблицы, линии — связи.

!!! question "Сделай"
    Что показывают линии между таблицами?

??? success "Проверить"
    Связи — внешние ключи. Например, `packs.user_id → users.id`.

## Шаг 2 · Открываем ERD Tool в pgAdmin

!!! tip "Правило"
    В pgAdmin: правый клик по базе → **ERD Tool**. Он строит диаграмму из уже
    существующих таблиц.

Порядок в pgAdmin:

1. Слева выбери базу `postgres`.
2. Правый клик → **ERD Tool** (или **Tools → ERD Tool**).
3. Слева в панели выбери таблицы → **Add** — они появятся на холсте.
4. Связи подтянутся по внешним ключам.
5. **File → Export** → сохрани файл/картинку, и сделай скриншот.

!!! question "Сделай"
    Почему ER-диаграмму строят **после** третьей транзакции?

??? success "Проверить"
    Связи появляются только после `foreign key`. Без них диаграмма будет без
    линий.

## Шаг 3 · Таблица расчёта температуры

В ТЗ есть **Таблица 1** — виртуальная поправка `ΔT_V` в зависимости от `t0`:

| `t0` | Ниже 0 | 0–5 | 10–15 | 20 | 25 | 30 | 40 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `ΔT_V` | 0 | 0.5 | 1 | 1.5 | 2 | 3.5 | 4.5 |

Оформим её как таблицу `temperature_correction`:

```sql
create table temperature_correction(
	id integer primary key,
	t0_from numeric,
	t0_to   numeric,
	delta_tv numeric
);
```

!!! question "Сделай"
    Зачем нужны `t0_from` и `t0_to`?

??? success "Проверить"
    Это границы диапазона температуры. По ним потом ищут нужную поправку `delta_tv`.

## Шаг 4 · Данные для таблицы температуры

```sql
insert into temperature_correction (id, t0_from, t0_to, delta_tv) values
	(1, null, 0,   0),
	(2, 0,    5,   0.5),
	(3, 10,   15,  1),
	(4, 20,   20,  1.5),
	(5, 25,   25,  2),
	(6, 30,   30,  3.5),
	(7, 40,   40,  4.5);
```

!!! question "Сделай"
    Сколько строк получится?

??? success "Проверить"
    Семь — по числу столбцов в Таблице 1 из ТЗ.

## Шаг 5 · Куда добавить таблицу

!!! tip "Правило"
    Задание говорит «в исходный скрипт». Значит, `create table
    temperature_correction` идёт в **первую** транзакцию (структура), а её
    `insert` — во **вторую** (данные). Связи у неё нет — это отдельный справочник.

!!! question "Сделай"
    В какую транзакцию попадёт `create table temperature_correction`?

??? success "Проверить"
    В первую — где создаётся структура.

## Наивные вопросы

!!! question "ERD Tool и `\d` — одно и то же?"
    Нет. `\d` — текстовое описание одной таблицы. ERD — картинка всех таблиц и
    связей.

!!! question "А если ERD Tool не открывается?"
    Убедись, что ты подключён к базе `postgres` (не к серверу) и что pgAdmin
    запущен. ERD Tool строит диаграмму именно из подключённой базы.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** будет ли линия между `temperature_correction` и другими таблицами?
    2. **Объясни**, почему данные таблицы температуры идут во вторую транзакцию.
    3. **Напиши** `create table` для двух колонок: `t0 numeric`, `delta_tv numeric`.

??? success "Проверить"
    1. Нет — у неё нет внешних ключей.
    2. Потому что таблица создаётся в первой, а наполняется данными во второй.
    3. `create table t(t0 numeric, delta_tv numeric);`
