# 1. Данные и DML: что анализируем

Прежде чем писать анализ, надо понять **на каких данных** он работает и откуда
они взялись. Это и есть «создать DML-скрипт с набором данных».

!!! abstract "Цель урока"
    Ты поймёшь, что такое DML, как выглядит схема базы измерений и как ИИ
    заполняет её данными.

## Шаг 1 · Что такое DML

!!! note "Определение"
    **DML** (Data Manipulation Language) — команды, которые меняют **данные**, а
    не структуру: `INSERT` (добавить строки), `UPDATE` (изменить), `DELETE` (удалить).

```sqlplay
-- @seed artillery_my
insert into eq_types (id, name) values (3, 'АМК');

select * from eq_types order by id;
```

!!! question "Сделай"
    Чем `insert` отличается от `create table`?

??? success "Проверить"
    `insert` добавляет **строки** в уже существующую таблицу. `create table`
    создаёт саму **таблицу** (это DDL). В домашке №3 нужен именно `insert`.

## Шаг 2 · Схема базы

База после второй домашки состоит из таблиц:

| Таблица | Что хранит |
| --- | --- |
| `positions` | должности |
| `eq_types` | типы оборудования (`ДМК`, `ВР`) |
| `users` | сотрудники |
| `packs` | пачки — один сеанс измерения |
| `parametrs` | измерения: `pack_id`, `parameter_type_id`, `value` |
| `base_units` | физические величины |
| `units` | единицы измерения |
| `parameter_types` | параметры (название + единица) |

!!! question "Сделай"
    Где хранится **значение** измерения, а где — **описание** параметра?

??? success "Проверить"
    Значение — в `parametrs.value`. Описание (название и единица) — в
    `parameter_types` (через `unit_id` → `units`).

## Шаг 3 · Типовые параметры и диапазоны

Параметры берём строго из ТЗ:

| id | параметр | единица | диапазон |
|----|----------|---------|----------|
| 1 | высота метеопоста | м | любое число |
| 2 | температура | °C | −58…58 |
| 3 | давление | мм рт. ст. | 500…900 |
| 4 | направление ветра | б. д. у. | 0…59 |
| 5 | скорость ветра | м/с | 0…15 |
| 6 | дальность сноса пуль | м | 0…150 |

!!! question "Сделай"
    Что означает «значение вне диапазона» для температуры?

??? success "Проверить"
    `value < -58` или `value > 58`. Например, `100` — вне диапазона.

## Шаг 4 · Кто пишет данные

DML-скрипт с данными пишет **ИИ** (GigaChat или YandexAI) по твоему промту.
Промт прикладываешь в Pull Request.

Промт должен содержать:

- таблицы и их колонки;
- что уже есть в базе (сотрудники `1`, `2`, параметры `1..6`);
- что добавить (сотрудника, пачки, измерения);
- допустимые диапазоны значений.

!!! question "Сделай"
    Почему в промте важно указать диапазоны?

??? success "Проверить"
    Иначе ИИ выдумает значения вне диапазона — а анализ как раз должен их ловить.

## Шаг 5 · Зачем анализировать данные

!!! tip "Правило"
    Данные от ИИ почти всегда содержат ошибки. Задача анализа — **найти их
    запросами**, а не глазами.

Типичные ошибки ИИ:

- разное число измерений у пользователей;
- пустые пачки;
- пачка без части параметров;
- значения вне диапазона;
- единица измерения не та.

!!! question "Сделай"
    Какой из 5 вопросов анализа ищет «пачка без параметров»?

??? success "Проверить"
    Вопрос 2: «У нас нет пустых пачек измерения?»

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** что вернёт `select count(*) from parametrs where pack_id = 8;`, если пачка 8 пустая?
    2. **Объясни**, чем DML отличается от DDL.
    3. **Напиши** `insert`, который добавляет сотрудника `3` с должностью `3`.

??? success "Проверить"
    1. `0` — в пустой пачке нет измерений.
    2. DML меняет данные (`insert/update/delete`), DDL — структуру (`create/alter/drop`).
    3. `insert into users (id, full_name, position_id) values (3, 'Сидоров', 3);`
