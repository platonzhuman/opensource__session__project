# 7. Сдача: скриншоты и Pull Request

Все 5 запросов готовы. Осталось собрать их в один скрипт и оформить сдачу.

!!! abstract "Цель урока"
    Ты соберёшь скрипт анализа и откроешь отдельный Pull Request.

## Шаг 1 · Собери скрипт

Файл: `_Infra/scripts/home_work_three` (или `home_work_three.sql`). Внутри — 5
запросов, каждый с коротким комментарием:

```sql
-- 1. у каждого пользователя одинаковое число измерений?
...
-- 2. пустые пачки
...
-- 3. пачки не с 5 параметрами
...
-- 4. значения вне диапазона
...
-- 5. неверные единицы
...
```

!!! question "Сделай"
    Сколько запросов в скрипте анализа?

??? success "Проверить"
    Пять — по одному на каждый вопрос. Плюс отдельный DML-скрипт с данными от ИИ.

## Шаг 2 · Прогони и сними скриншоты

Задание требует **скриншот к каждому запросу**. Порядок:

1. Открой pgAdmin → базу `postgres`.
2. Выполни первый запрос → сними окно с результатом.
3. Повтори для остальных четырёх.

!!! question "Сделай"
    Что должно быть видно на скриншоте?

??? success "Проверить"
    Сам запрос и таблица результата (например, проблемные пачки `4` и `8`).

## Шаг 3 · Приложи промт

Промт, по которому ИИ сгенерировал данные, прикладываешь в Pull Request
(текстом или файлом `promt.md`).

!!! question "Сделай"
    Зачем в PR прикладывать промт?

??? success "Проверить"
    Чтобы было видно, **как** получены данные и что именно просили у ИИ.

## Шаг 4 · Ветка и Pull Request

```bash
git checkout main
git pull
git checkout -b homework_three

git add _Infra/scripts/home_work_three_dml.sql
git add _Infra/scripts/home_work_three
git add _Infra/scripts/promt.md
git commit -m "homework three: data and analysis"
git push -u origin homework_three
```

Дальше на GitHub: **Compare & pull request** → base `main`, compare
`homework_three`. В описание — что сделано и приложи скриншоты.

!!! question "Сделай"
    Что проверить перед коммитом?

??? success "Проверить"
    `git status` — что в коммит идут только нужные файлы (два скрипта и промт),
    без лишнего.

!!! tip "Правило"
    Одна домашка — одна ветка — один Pull Request. Лишние файлы не добавляй.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** сколько файлов должно уйти в PR?
    2. **Объясни**, зачем отдельный DML-скрипт, а не данные внутри анализа.
    3. **Напиши** команды: создать ветку `homework_three` и закоммитить.

??? success "Проверить"
    1. Три: `home_work_three_dml.sql`, `home_work_three`, промт (+ скриншоты в описании).
    2. Данные и анализ — разные задачи: данные наполняют базу, анализ её проверяет.
    3. `git checkout -b homework_three` → `git add ...` → `git commit -m "homework three"`.
