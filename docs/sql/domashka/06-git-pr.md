# 6. Git-ветка и Pull Request

Последний пункт домашки — организационный. После урока ты оформишь работу
отдельной веткой и создашь PR.

## Зачем отдельная ветка

Ветка изолирует работу от основной линии. Пока ты не слил её, `main` остаётся
рабочим. Преподаватель видит ровно твои изменения в виде Pull Request.

## Шаги

Создать и переключиться на ветку:

```bash
git checkout -b homework-sql
```

Добавить скрипт и закоммитить:

```bash
git add homework.sql
git commit -m "Add homework SQL script"
```

Отправить ветку на сервер:

```bash
git push -u origin homework-sql
```

После `push` GitHub или GitLab покажет кнопку **Compare & pull request**. Нажми
её, заполни заголовок и описание, создай PR.

## Что приложить в PR

- Файл `homework.sql`.
- Скриншот результата `SELECT` (пункт 2 домашки).
- Короткое описание: какие таблицы создал, чем связал.

## Частые ошибки

!!! warning "Ошибка"
    Коммитить прямо в `main`. Тогда отдельной ветки нет, и требование не
    выполнено. Создай ветку до первого коммита.

!!! warning "Ошибка"
    Забыть `git push`. Без него ветки нет на сервере, и PR создать нельзя.

!!! warning "Ошибка"
    Приложить скриншот отдельным коммитом в ту же ветку — нормально. Но не
    вставляй пароли и строки подключения к базе в файлы.

## Проверка

- [ ] Есть ветка с понятным именем.
- [ ] В ней лежит `homework.sql`.
- [ ] PR создан и содержит скриншот.
- [ ] `main` не тронут.
