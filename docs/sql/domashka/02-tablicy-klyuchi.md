# 2. Таблицы и уникальные коды

Создаём таблицы и решаем требование «у каждой записи уникальный код». После урока
ты будешь уверенно писать `CREATE TABLE` с ключами и ограничениями.

## Команда CREATE TABLE

```sql
CREATE TABLE positions (
    id   INTEGER      NOT NULL,
    name VARCHAR(100) NOT NULL,
    CONSTRAINT pk_positions PRIMARY KEY (id)
);
```

Разбор:

| Часть | Смысл |
|-------|-------|
| `CREATE TABLE positions` | создать таблицу с именем `positions` |
| `id INTEGER NOT NULL` | столбец `id`, целое число, пустым быть не может |
| `name VARCHAR(100) NOT NULL` | строка до 100 символов, не пустая |
| `CONSTRAINT pk_positions PRIMARY KEY (id)` | `id` — первичный ключ |

## Уникальный код записи — это PRIMARY KEY

!!! note "Определение"
    **PRIMARY KEY** (первичный ключ) — столбец или набор столбцов, значения
    которого уникальны для каждой строки и не могут быть пустыми.

Требование «у каждой записи уникальный код» закрывается первичным ключом. Обычно
это столбец `id`:

```sql
CONSTRAINT pk_positions PRIMARY KEY (id)
```

Два правила первичного ключа:

- значения не повторяются;
- значение не может быть `NULL`.

## Уникальный код таблицы

Требование «у каждой таблицы уникальный код» — это про то, что **у каждой
таблицы есть свой первичный ключ**. У `positions` он называется `pk_positions`,
у следующей таблицы будет свой. Имена ограничений делают уникальными, чтобы они
не конфликтовали внутри одной базы.

## Ограничение UNIQUE

`UNIQUE` запрещает повтор значений в столбце, но, в отличие от ключа, допускает
`NULL`. Пригодится для названий: две должности с именем «Оператор» не нужны.

```sql
CREATE TABLE equipment_types (
    id   INTEGER      NOT NULL,
    name VARCHAR(100) NOT NULL,
    CONSTRAINT pk_equipment_types PRIMARY KEY (id),
    CONSTRAINT uq_equipment_types_name UNIQUE (name)
);
```

`id` — уникальный код записи, `name` — уникальное название.

## Типы данных

Для этой домашки хватит четырёх:

| Тип | Для чего | Пример |
|-----|----------|--------|
| `INTEGER` | целые числа, коды, количество | `10` |
| `VARCHAR(n)` | строки до `n` символов | `'Иванов Иван'` |
| `DATE` | дата | `DATE '2026-09-01'` |
| `DECIMAL(p, s)` | дробные числа | `DECIMAL(10, 2)` |

!!! tip "Длина строки"
    `VARCHAR(100)` — не «строка ровно 100 символов», а «максимум 100». Короткое
    значение займёт ровно столько, сколько нужно.

## Именование

Идентификаторы пишем латиницей: `positions`, `users`, `packs`. Так их не нужно
брать в кавычки, и скрипт остаётся переносимым. Русские названия — в данных:

```sql
INSERT INTO positions (id, name) VALUES (1, 'Оператор');
```

## Частые ошибки

!!! warning "Ошибка"
    Забыть `PRIMARY KEY`. Тогда уникальность записей ничем не гарантирована, и
    требование домашки не выполнено.

!!! warning "Ошибка"
    Ставить `PRIMARY KEY` на `name`, если название может повторяться. Под
    уникальное название — `UNIQUE`, под код — `PRIMARY KEY`.
