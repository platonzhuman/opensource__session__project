## Что делает скрипт

Скрипт готовит инструмент для одной задачи: по температуре найти **отрезок**
таблицы поправок и вычислить поправку **линейной интерполяцией**.

```text
температура 23
    ↓
отрезок: (20, 1.5) → (25, 2)
    ↓
доля пути: (23 - 20) / (25 - 20) = 0.6
    ↓
поправка: 1.5 + 0.6 * (2 - 1.5) = 1.8
```

Скрипт делает четыре вещи:

1. удаляет старый тип;
2. создаёт тип `interpolation_type`;
3. создаёт функцию поиска отрезка;
4. создаёт функцию расчёта.

## Откуда берётся `par_x`

`par_x` — это **значение, для которого мы считаем поправку**. В этой задаче
`par_x` — температура. Функция `interpolate` не ищет таблицу и не знает, где
взялась температура: она получает готовое число и готовый отрезок.

Вызов выглядит так:

```sql
select public.interpolate(
    23,
    public.get_interpolation_type_correction(23)
);
```

Что здесь происходит:

1. `23` — это `par_x`.
2. `get_interpolation_type_correction(23)` возвращает отрезок `(20, 1.5, 25, 2)`.
3. Этот отрезок становится `par_point`.
4. `interpolate` считает `y` для `x = 23`.

Можно думать так:

```text
par_x = 23                  ← температура, для которой ищем поправку
par_point = (20, 1.5, 25, 2) ← отрезок, который нашла первая функция
```

Внутри формулы `par_x` встречается только здесь:

```sql
par_x - par_point.x0
```

То есть мы считаем, насколько `par_x` отошёл от левой точки отрезка.

Важно: `par_x` и отрезок должны быть согласованы. Если передать `par_x = 30`,
а отрезок от `23`, функция не заметит ошибку и просто экстраполирует.
Поэтому в домашке передавай **одну и ту же температуру** в обе функции.

## Кто передаёт число в `par_temperature`

Вот эта строка — **не вызов функции**, а её описание:

```sql
create function public.get_interpolation_type_correction(par_temperature numeric)
```

`par_temperature` здесь — не конкретное число, а имя параметра. Это место, куда
попадёт значение при вызове. В самом `home_work_five` **нет вызова** этой
функции: скрипт только создаёт её.

Число появляется позже, когда ты пишешь:

```sql
select public.get_interpolation_type_correction(23);
```

В этот момент:

```text
23 → par_temperature
```

И дальше внутри функции уже работает `par_temperature = 23`.

Если вызывать из таблицы, число берётся из колонки:

```sql
select public.get_interpolation_type_correction(t.temperature)
from some_table t;
```

Если вызывать из приложения, число приходит из поля формы:

```sql
select public.get_interpolation_type_correction($1);
```

Главное:

- `par_temperature` в `create function` — это **заполнитель**, а не значение;
- значение появляется только в `select ... (23)`;
- в `home_work_five` нет готового вызова — его нужно сделать отдельно;
- в вызове `interpolate` температура передаётся дважды: как `par_x` и внутри
  `get_interpolation_type_correction(...)`.

## Формула без магии

```text
y = y0 + (x - x0) * (y1 - y0) / (x1 - x0)
```

- `x0, y0` — левая точка;
- `x1, y1` — правая;
- `(x - x0)` — сколько прошли по x;
- `(x1 - x0)` — длина отрезка по x;
- `(y1 - y0)` — изменение y;
- отношение — доля пути.

Для 23 на отрезке `(20, 1.5) → (25, 2)`:

```text
1.5 + (23 - 20) * (2 - 1.5) / (25 - 20)
= 1.5 + 3 * 0.5 / 5
= 1.8
```

## Где код может упасть

### 1. Таблица называется иначе

В `home_work_four` создаётся `temperature_correction` с интервалами
`t0_from, t0_to, delta_tv`, а функция ищет `calc_temperature_correction` с
колонками `temperature, correction`.

Если запускать скрипт на чистой базе, будет:

```text
relation "calc_temperature_correction" does not exist
```

Нужно либо создать таблицу/представление с точками, либо явно сказать
преподавателю, откуда берётся `calc_temperature_correction`.

### 2. `commit` внутри `DO`

Скрипт фиксирует каждый шаг отдельно. Если четвёртый шаг упадёт, первые три
останутся в базе. Для учебного скрипта это удобно, для продакшена — риск.
Не оборачивай весь вызов в транзакцию и не жди полного отката.

### 3. `drop type ... cascade`

`cascade` удалит не только тип, но и функции, которые от него зависят. При
повторном запуске это нормально, но в общей базе может удалить лишнее.

### 4. Нет `strict` и проверки пустой таблицы

Если `calc_temperature_correction` пустая или в ней нет подходящей строки,
`select into` оставит поля `v` пустыми. Лучше добавить проверку:

```sql
if v.x0 is null then
    raise exception 'Нет отрезка для температуры %', par_temperature;
end if;
```

### 5. Разрыв 5–10

В таблице есть точки `5` и `10`. Код линейно соединяет их. Если по ТЗ между
этими точками должно быть другое правило, это нужно уточнить.

## Как рассказать на уроке за 60 секунд

1. «Скрипт создаёт тип из четырёх чисел: две точки отрезка».
2. «Первая функция ищет отрезок по температуре: `lead` даёт следующую точку».
3. «Вторая функция считает линейную интерполяцию по формуле».
4. «Для 23° отрезок 20–25, доля 0.6, поправка 1.8».
5. «Ниже нуля — 0, после 40 — последняя поправка, деление на ноль защищено».
