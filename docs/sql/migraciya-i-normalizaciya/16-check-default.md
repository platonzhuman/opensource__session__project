# 16. CHECK и DEFAULT: ограничения из ТЗ

В ТЗ у каждого параметра есть допустимый диапазон: температура от `-58` до `58`,
давление от `500` до `900`. Эти правила можно зашить прямо в базу.

!!! abstract "Цель урока"
    Ты научишься запрещать неверные значения через `check` и подставлять значения
    по умолчанию через `default`.

## Шаг 1 · NOT NULL — значение обязательно

!!! tip "Правило"
    `not null` запрещает пустое значение. Без него в столбце может оказаться `NULL`.

```sqlplay
-- @seed base
create table demo (
    id    integer not null,
    value numeric(8,2) not null
);
insert into demo (id, value) values (1, null);
```

!!! question "Сделай"
    Что произойдёт?

??? success "Проверить"
    Ошибка `not null`: значение обязательно, а передан `null`.

## Шаг 2 · DEFAULT — значение по умолчанию

!!! tip "Правило"
    `default <значение>` подставляется, если столбец не указан во `insert`.

```sqlplay
-- @seed base
create table demo (
    id    integer not null,
    value numeric(8,2) not null default 0
);
insert into demo (id) values (1);
select * from demo;
```

!!! question "Сделай"
    Что окажется в `value`?

??? success "Проверить"
    `0` — значение по умолчанию. Мы его не передавали.

## Шаг 3 · CHECK — допустимый диапазон

!!! tip "Правило"
    `check (условие)` пропускает только строки, где условие истинно.

```sqlplay
-- @seed base
create table demo (
    id    integer not null,
    value numeric(8,2) not null,
    constraint ck_demo_value check (value between -58 and 58)
);
insert into demo (id, value) values (1, 100);
```

!!! question "Сделай"
    Почему вставка падает?

??? success "Проверить"
    `100` выходит за диапазон `-58…58`. `check` не пустил значение. `between a and b`
    значит «от `a` до `b` включительно».

## Шаг 4 · Ограничения из ТЗ

| Параметр | Диапазон | Единица |
| --- | --- | --- |
| Высота метеопоста | любые целые (в т. ч. отрицательные) | м |
| Температура | `-58 … 58` | °C |
| Давление | `500 … 900` | мм рт. ст. |
| Направление ветра | `0 … 59` | б. д. у. |
| Скорость ветра | `0 … 15` | м/с |
| Дальность сноса пуль | `0 … 150` | м |

!!! question "Сделай"
    Напиши `check`, запрещающий давление вне `500…900`.

??? success "Проверить"
    `constraint ck_pressure check (pressure between 500 and 900)` — но в EAV-модели
    значение одно (`value`), а диапазон зависит от параметра. Как это решить — вопрос
    ниже.

## Шаг 5 · Проблема EAV и диапазонов

В нормализованной таблице `value` один на все параметры, а диапазоны разные. Значит,
один общий `check` на `value` не подходит.

!!! question "Сделай"
    Где в таком случае хранить допустимый диапазон?

??? success "Проверить"
    В справочнике: добавить в `parameter_types` столбцы `min_value` и `max_value` и
    проверять значение приложением или триггером. Это честное ограничение EAV —
    платим гибкостью ради разных наборов параметров.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `not null` | значение обязательно |
| `default 0` | подставить `0`, если не задано |
| `check (value between -58 and 58)` | допустимый диапазон |
| `constraint ck_...` | имя ограничения |

## Откуда числа

`-58`, `58`, `500`, `900`, `0…59`, `0…15`, `0…150` — прямо из ТЗ, раздел
«Ячейки исходных данных». Это требования, а не данные.

## Наивные вопросы

!!! question "Зачем `check`, если можно проверить в приложении?"
    База — последний рубеж. Приложение может обойтись, а `check` сработает всегда,
    для любого, кто пишет в базу.

!!! question "Можно ли несколько `check` на одну таблицу?"
    Да, сколько угодно, у каждого своё имя.

!!! question "`default now()` — это `DEFAULT`?"
    Да, `default now()` подставляет текущее время при вставке, если столбец не указан.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** что вернёт вставка температуры `70` при `check (value between -58 and 58)`?
    2. **Объясни**, зачем нужен `default`.
    3. **Напиши** `check` для скорости ветра `0…15`.

??? success "Проверить"
    1. Ошибку `check` — `70` вне диапазона.
    2. Чтобы не писать значение каждый раз и получить разумную подстановку.
    3. `check (value between 0 and 15)` (в справочнике — для конкретного параметра).
