# 4. FOREIGN KEY и связи

Этот урок — про то, как таблицы соединяются. Без внешних ключей база превращается
в набор несвязанных списков, и запрос из домашки собрать не получится.

!!! abstract "Цель урока"
    Ты поймёшь, что такое `FOREIGN KEY`, как выглядит связь «один-ко-многим» и как
    база защищает связи от мусора.

## Шаг 1 · Как связать пачку с сотрудником

У пачки есть код сотрудника, который её сделал.

```sqlplay
-- @seed artillery
select id, emploee_id, measurment_type_id, started
from measurment_baths
order by id;
```

Столбец `emploee_id` хранит **код** сотрудника, а не его имя. Так имя хранится один
раз — в `employees`.

!!! question "Сделай"
    Какая связь у пачки `id = 2`? Найди её сотрудника.

??? success "Проверить"
    `emploee_id = 1`. Сотрудник с `id = 1` — `Воловиков Александр Сергеевич`.

## Шаг 2 · FOREIGN KEY — ссылка на чужой ключ

!!! note "Определение"
    **FOREIGN KEY** (внешний ключ) — столбец, значения которого должны существовать
    в первичном ключе другой таблицы. Это объявленная связь.

```sqlplay
-- @seed artillery
select constraint_name
from information_schema.table_constraints
where table_name = 'measurment_baths' and constraint_type = 'FOREIGN KEY';
```

!!! question "Сделай"
    На какие таблицы ссылается `measurment_baths`?

??? success "Проверить"
    На `employees` (через `emploee_id`) и на `measurment_types` (через
    `measurment_type_id`). Два внешних ключа.

## Шаг 3 · Связь «один-ко-многим»

Один сотрудник — много пачек. Это связь **один-ко-многим**: «один» со стороны
`employees`, «многие» со стороны `measurment_baths`.

!!! question "Сделай"
    Посчитай, сколько пачек у каждого сотрудника.

```sqlplay
-- @seed artillery
select e.name, count(*) as пачек
from employees as e
inner join measurment_baths as b on b.emploee_id = e.id
group by e.name
order by e.name;
```

??? success "Проверить"
    `Воловиков` — 2, `Петров` — 2, `Сидоров` — 1. `group by` и `count(*)` посчитают
    это за нас.

## Шаг 4 · База не даст сломать связь

Попробуй привязать пачку к несуществующему сотруднику.

```sqlplay
-- @seed artillery
insert into measurment_baths (id, emploee_id, measurment_type_id, started)
values (99, 555, 1, '2026-09-06 00:00:00');
```

!!! question "Сделай"
    Почему база отказывается это записать?

??? success "Проверить"
    Сотрудника с `id = 555` нет в `employees`. Внешний ключ запрещает ссылаться в
    пустоту — это **ссылочная целостность**.

## Шаг 5 · Посчитай связанные строки

!!! question "Сделай"
    Посчитай, сколько измерений у каждой пачки.

```sqlplay
-- @seed artillery
select b.id as пачка, count(i.id) as измерений
from measurment_baths as b
inner join measurment_input_params as i on i.measurment_bath_id = b.id
group by b.id
order by b.id;
```

??? success "Проверить"
    У каждой пачки по `5` измерений. Связь «один-ко-многим» позволяет собрать все
    строки потомка по коду родителя.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `emploee_id` | столбец-ссылка на код сотрудника |
| `foreign key (emploee_id) references employees (id)` | связь пачки с сотрудником |
| «один-ко-многим» | одна строка `employees` ↔ много строк `measurment_baths` |
| `count(*)` | число строк в группе |

## Откуда числа

`emploee_id = 1` у пачки `2` — из данных. Число пачек `2/2/1` — результат
`count(*)` по группам. Код `555` придуман специально, чтобы показать отказ базы.

## Наивные вопросы

!!! question "Почему не хранить имя сотрудника прямо в пачке?"
    Тогда имя повторится в каждой пачке, и при переименовании придётся править всё.
    Это та же аномалия, что в уроке 1.

!!! question "Что будет, если удалить сотрудника, у которого есть пачки?"
    Внешний ключ не даст удалить — сначала надо решить судьбу пачек. Это защита от
    «висячих» ссылок.

!!! question "Можно ли ссылаться на не-ключевой столбец?"
    Стандарт требует, чтобы цель ссылки была уникальной (обычно это `PRIMARY KEY`).
