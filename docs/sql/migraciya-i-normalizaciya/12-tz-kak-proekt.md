# 12. Читаем ТЗ как проектировщик

Домашка сделана. Дальше — углубление: как из технического задания вырастает схема
базы. Разбираем ТЗ артиллерийского комплекса.

!!! abstract "Цель урока"
    Ты научишься вытаскивать из ТЗ сущности, их свойства и связи.

## Шаг 1 · Найди входные данные

В ТЗ перечислены входные данные: тип оборудования, высота `ДМК`, температура,
давление, направление ветра, скорость ветра. Плюс для `ВР` вместо скорости ветра —
дальность сноса пуль.

!!! question "Сделай"
    Что из этого — **значение** измерения, а что — **описание** параметра?

??? success "Проверить"
    Значение — конкретное число (`100`, `15.0`). Описание — что это за параметр и в
    чём измеряется (`Высота`, `м`). Значения живут в измерениях, описания — в
    справочниках.

## Шаг 2 · Выпиши сущности

!!! question "Сделай"
    Назови сущности ТЗ и их примерные таблицы.

??? success "Проверить"
    Сотрудник (`employees`), должность (`military_ranks`), оборудование
    (`measurment_types`), тип параметра (`parameter_types`), единица (`units`),
    физическая величина (`base_units`), пачка (`measurment_baths`), измерение
    (`measurment_input_params`).

## Шаг 3 · Увидь разницу ДМК и ВР

```sqlplay
-- @seed artillery
select
    m.short_name as оборудование,
    p.name       as параметр
from measurment_types as m
inner join measurment_baths as b       on b.measurment_type_id = m.id
inner join measurment_input_params as i on i.measurment_bath_id = b.id
inner join parameter_types as p         on p.id = i.parameter_type_id
where m.short_name = 'ВР'
order by b.id, p.id;
```

!!! question "Сделай"
    Какой параметр есть у `ВР`, но которого нет у `ДМК`?

??? success "Проверить"
    `Дальность сноса пуль`. У `ДМК` вместо неё — `Скорость ветра`. Это разные наборы
    параметров для одного и того же журнала измерений.

## Шаг 4 · Свяжи требования со схемой

!!! tip "Правило"
    Если набор параметров отличается для разных случаев — его хранят **строками**
    (EAV), а не столбцами. Тогда новое оборудование не требует менять структуру.

!!! question "Сделай"
    Почему широкая таблица из первого скрипта плохо подходит под ДМК **и** ВР сразу?

??? success "Проверить"
    У них разные параметры: у `ВР` есть «дальность сноса пуль», у `ДМК` — «скорость
    ветра». В широкой таблице пришлось бы держать оба столбца, и у половины строк они
    пустые. EAV хранит только реально измеренные параметры.

## Шаг 5 · Свяжи параметр с единицей

!!! question "Сделай"
    Выведи параметры, у которых единица — метр (`м`).

```sqlplay
-- @seed artillery
select p.name
from parameter_types as p
inner join units as u on u.id = p.unit_id
where u.short_name = 'м'
order by p.id;
```

??? success "Проверить"
    `Высота метеопоста` и `Дальность сноса пуль` — оба измеряются в метрах. Единица
    хранится один раз и переиспользуется.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| входные данные ТЗ | что измеряем и в чём |
| ДМК / ВР | типы оборудования из справочника `measurment_types` |
| EAV | строки вместо столбцов — под разные наборы параметров |
| связь пачка → измерения | одна пачка, много измерений |

## Откуда числа

Числа `100`, `15.0`, `750` — из раздела ТЗ «значения по умолчанию». Оборудование
`ДМК`/`ВР` — из ТЗ. Все факты взяты из документа, не придуманы.

## Наивные вопросы

!!! question "Зачем хранить параметр отдельной сущностью, а не текстом?"
    Текст нельзя связать с единицей измерения и с типом оборудования. Сущность
    `parameter_types` даёт единицу и уникальность названия.

!!! question "Как из ТЗ понять, что связь «один-ко-многим»?"
    По смыслу: у одной пачки много измерений; у одного сотрудника много пачек; у одной
    единицы много параметров.

!!! question "Почему журнал измерений — это пачки, а не одна таблица?"
    Пачка — один сеанс измерения с одной датой и одним оператором. Это естественная
    граница, к которой привязаны все параметры.
