# 17. Транзакции: миграция целиком или ничего

Миграция — это несколько команд подряд. Если третья упадёт, а первые две уже
применились, база останется в половинчатом состоянии. Транзакции это лечат.

!!! abstract "Цель урока"
    Ты научишься оборачивать миграцию в транзакцию и откатывать её при ошибке.

## Шаг 1 · Проблема половинчатой миграции

Представь: создали новую таблицу, перенесли данные, а `drop` старой упал. В базе —
две таблицы параметров, и непонятно, какая рабочая.

!!! question "Сделай"
    Чем опасна такая половинчатая миграция?

??? success "Проверить"
    Данные могут дублироваться или противоречить друг другу, а приложение — читать не
    ту таблицу. База в неопределённом состоянии.

## Шаг 2 · BEGIN и COMMIT

!!! tip "Правило"
    `begin` открывает транзакцию, `commit` фиксирует все команды разом. До `commit`
    изменения не видны окончательно.

```sqlplay
-- @seed base
begin;
create table tx_demo (id integer, name text);
insert into tx_demo values (1, 'a');
commit;

select * from tx_demo;
```

!!! question "Сделай"
    Что попадёт в `tx_demo` после `commit`?

??? success "Проверить"
    Одна строка `(1, 'a')`. Транзакция зафиксирована целиком.

## Шаг 3 · ROLLBACK — отменить всё

```sqlplay
-- @seed base
begin;
create table tx_demo (id integer, name text);
insert into tx_demo values (1, 'a');
rollback;

select table_name from information_schema.tables
where table_schema = 'public' and table_name = 'tx_demo';
```

!!! question "Сделай"
    Что вернёт последний запрос?

??? success "Проверить"
    Ничего. `rollback` отменил всю транзакцию — таблицы `tx_demo` не осталось.

## Шаг 4 · Атомарность

!!! note "Определение"
    **Атомарность** — свойство транзакции выполниться целиком или не выполниться
    вовсе. Это буква `A` в ACID.

!!! question "Сделай"
    Оберни миграцию в транзакцию мысленно: если `drop` упадёт, что произойдёт с уже
    созданными таблицами?

??? success "Проверить"
    При `rollback` они не останутся — база вернётся к состоянию до `begin`. Именно
    поэтому миграции заворачивают в транзакцию.

## Шаг 5 · Как применить к домашки

!!! tip "Правило"
    Оберни весь второй скрипт в `begin; ... commit;`. Если что-то упадёт — `rollback`,
    и база как была.

```sql
begin;
-- alter table ... add constraint ...
-- create table base_units ...
-- insert ...
-- create table measurment_input_params_new ...
-- insert into ... select ... union all ...
-- drop table measurment_input_params;
-- alter table measurment_input_params_new rename to measurment_input_params;
commit;
```

!!! question "Сделай"
    Почему `commit` ставят в самом конце, а не после каждой команды?

??? success "Проверить"
    Потому что весь смысл — зафиксировать миграцию **целиком**. Промежуточный `commit`
    снова сделает её половинчатой.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `begin` | начать транзакцию |
| `commit` | зафиксировать все команды |
| `rollback` | отменить всё с момента `begin` |
| `ACID` | атомарность, согласованность, изоляция, долговечность |

## Откуда числа

Число строк `(1, 'a')` — из вставки в примере. Никаких вычислений, только демонстрация
поведения транзакции.

## Наивные вопросы

!!! question "Можно ли откатить обычную команду без `begin`?"
    Каждая команда без `begin` — сама себе транзакция и фиксируется сразу. Откатить
    её отдельно нельзя.

!!! question "Что будет, если закрыть соединение в середине транзакции?"
    Незафиксированная транзакция откатится автоматически.

!!! question "Обязательна ли транзакция в домашки?"
    Формально нет, но это признак грамотной миграции. Если скрипт запускается на
    реальных данных — транзакция обязательна.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** что окажется в базе после `begin; create table t...; rollback;`?
    2. **Объясни**, что такое атомарность своими словами.
    3. **Напиши** каркас транзакции для миграции.

??? success "Проверить"
    1. Ничего — таблица не создастся.
    2. Транзакция выполняется целиком или не выполняется вовсе.
    3. `begin;` … команды миграции … `commit;`
