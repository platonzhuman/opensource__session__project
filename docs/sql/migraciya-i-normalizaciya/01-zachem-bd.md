# 1. Зачем БД: от листа к модели

Этот урок — про то, **почему** база данных разбита на таблицы, а не лежит одним
списком. Без этой идеи миграция из домашки выглядит как бессмысленная возня.

!!! abstract "Цель урока"
    Ты увидишь, что ломается, когда всё хранится в одной таблице, и поймёшь, зачем
    данные разделяют на сущности.

## Шаг 1 · Посмотри на «плохую» таблицу

Представь журнал измерений, куда пишут всё подряд одной строкой.

```sqlplay
-- @seed artillery
select
    b.started                 as "дата",
    e.name                    as "сотрудник",
    r.description             as "должность",
    m.short_name              as "оборудование",
    'Высота метеопоста'       as "параметр",
    p.value                   as "значение"
from measurment_baths as b
inner join employees as e        on e.id = b.emploee_id
inner join military_ranks as r   on r.id = e.military_rank_id
inner join measurment_types as m on m.id = b.measurment_type_id
inner join measurment_input_params as p on p.measurment_bath_id = b.id
where p.parameter_type_id = 1
order by b.id;
```

!!! question "Сделай"
    Запусти запрос. Сколько раз повторяется должность `Лейтенант`?

??? success "Проверить"
    Столько, сколько пачек у лейтенанта. Один и тот же факт («этот сотрудник —
    лейтенант») повторяется в каждой строке результата.

## Шаг 2 · Пойми, чем плох повтор

Если бы это был один большой лист Excel, одна и та же должность хранилась бы
столько раз, сколько строк. Что случится, если лейтенанта повысить до капитана?

!!! question "Сделай"
    Предскажи: если в одной строке исправить должность, а в другой забыть — что
    произойдёт с данными?

??? success "Проверить"
    Появится **аномалия**: один и тот же сотрудник будет одновременно и лейтенантом,
    и капитаном. База начнёт противоречить сама себе. Это называется **аномалией
    обновления**.

## Шаг 3 · Раздели на сущности

Вместо повторов мы храним каждый факт в своём месте:

- сотрудник — в `employees` (один раз);
- его должность — в `military_ranks` (справочник, один раз);
- измерение — в `measurment_baths` (пачка);
- значение параметра — в `measurment_input_params`.

Связь между строками держат **коды** (идентификаторы), а не текст.

!!! question "Сделай"
    Запусти и посмотри, сколько строк в каждом справочнике.

```sqlplay
-- @seed artillery
select 'employees' as таблица, count(*) as строк from employees
union all
select 'military_ranks', count(*) from military_ranks
union all
select 'measurment_baths', count(*) from measurment_baths;
```

??? success "Проверить"
    `employees` — 3, `military_ranks` — 3, `measurment_baths` — 5. Должность хранится
    3 раза (по числу разных должностей), а не 5 раз (по числу пачек).

## Шаг 4 · Найди справочник

Справочник — таблица, куда вынесены повторяющиеся значения, чтобы не дублировать их.

```sqlplay
-- @seed artillery
select * from military_ranks order by id;
```

!!! question "Сделай"
    Сколько строк в справочнике и кто на него ссылается?

??? success "Проверить"
    Три строки — три должности. На справочник ссылаются сотрудники через
    `military_rank_id`.

## Шаг 5 · Сформулируй правило

!!! question "Сделай"
    Закончи фразу: «Один факт хранится в базе …».

??? success "Проверить"
    «…один раз». Если один и тот же факт повторяется в строках — таблицу пора
    разделить.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `employees` | сущность «сотрудник» |
| `military_ranks` | сущность «должность», используется как справочник |
| `measurment_baths` | сущность «пачка» (один сеанс измерения) |
| `measurment_input_params` | сущность «измеренное значение» |
| `join ... on` | соединение строк двух таблиц по общему коду |

## Откуда числа

`3` сотрудника и `3` должности — из данных песочницы (`employees`, `military_ranks`).
`5` пачек — из `measurment_baths`. Это не вычисление, а факты из таблиц.

## Наивные вопросы

!!! question "Почему нельзя просто хранить имя должности текстом в каждой строке?"
    Можно, но тогда при переименовании придётся править все строки, и легко получить
    противоречие. Справочник хранит название один раз, остальные ссылаются на код.

!!! question "Что такое сущность?"
    Это объект предметной области, про который мы храним данные: сотрудник, пачка,
    оборудование. Обычно сущность = таблица.

!!! question "Зачем вообще коды, если есть текст?"
    Код — короткий и неизменный. Название может меняться, а код остаётся, и связи
    не рвутся.
