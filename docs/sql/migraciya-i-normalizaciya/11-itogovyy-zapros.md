# 11. Итоговый запрос в синтаксисе ANSI-92

Последний шаг домашки — переписать итоговый запрос. Требование «строго ANSI-92»
означает: объединять таблицы явным `JOIN ... ON`, а не списком через запятую.

!!! abstract "Цель урока"
    Ты научишься писать цепочку `INNER JOIN` и собирать строку «параметр и единица
    измерения» через конкатенацию.

## Шаг 1 · Два способа объединить таблицы

Старый синтаксис перечисляет таблицы через запятую, а условие связи прячет в `where`:

```sqlplay
-- @seed artillery
select b.id, e.name
from measurment_baths b, employees e
where b.emploee_id = e.id
order by b.id;
```

Новый (`ANSI-92`) держит условие рядом с таблицей:

```sqlplay
-- @seed artillery
select b.id, e.name
from measurment_baths as b
inner join employees as e on e.id = b.emploee_id
order by b.id;
```

!!! question "Сделай"
    Оба запроса вернут одно и то же. В чём выигрыш второго?

??? success "Проверить"
    Условие связи стоит вплотную к таблице. Забыть его сложнее, и запрос читается
    сверху вниз: «пачки, соединённые с сотрудниками по коду».

## Шаг 2 · Цепочка JOIN

Каждое следующее `inner join` добавляет одну таблицу и своё условие `on`.

```sqlplay
-- @seed artillery
select
    b.id           as "пачка",
    e.name         as "сотрудник",
    m.short_name   as "оборудование"
from measurment_baths as b
inner join employees as e        on e.id = b.emploee_id
inner join measurment_types as m on m.id = b.measurment_type_id
order by b.id;
```

!!! question "Сделай"
    Сколько таблиц соединяет этот запрос и сколько условий `on`?

??? success "Проверить"
    Три таблицы (`measurment_baths`, `employees`, `measurment_types`), два `on` — по
    одному на каждое присоединение.

## Шаг 3 · Склейка строк через ||

Оператор `||` соединяет строки в одну. Так собирают «параметр и единица».

```sqlplay
-- @seed artillery
select
    p.name || ' (' || u.short_name || ')' as "параметр"
from parameter_types as p
inner join units as u on u.id = p.unit_id
order by p.id;
```

!!! question "Сделай"
    Что вернёт первая строка результата?

??? success "Проверить"
    `Высота метеопоста (м)` — название параметра, скобка, короткое имя единицы,
    закрывающая скобка.

## Шаг 5 · Проверь каждую связь отдельно

!!! question "Сделай"
    Соедини измерения с типами параметров и посчитай строки.

```sqlplay
-- @seed artillery
select count(*) as строк
from measurment_input_params as i
inner join parameter_types as p on p.id = i.parameter_type_id;
```

??? success "Проверить"
    `25` — все измерения нашли свой тип. Если связь неверна, число строк упадёт:
    `inner join` отбросит несопоставленные.

!!! warning "Имя столбца"
    PostgreSQL ограничивает длину имени 63 байтами. У кириллицы символ занимает
    2 байта, поэтому заголовок «Наименование параметра и ед. измерения» (71 байт)
    обрежется до «Наименование параметра и ед. измер». Это ограничение базы, а не
    ошибка запроса.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `inner join t on условие` | присоединить таблицу и оставить только совпавшие строки |
| цепочка `join` | несколько присоединений подряд |
| `\|\|` | склейка строк |
| `as "Дата измерения"` | заголовок столбца в результате |

## Откуда числа

Коды связей (`emploee_id`, `measurment_type_id`, `parameter_type_id`, `unit_id`) —
из данных `artillery`. Строка `Высота метеопоста (м)` — склейка названий из
справочников.

## Наивные вопросы

!!! question "Что делает `inner join`, если связи нет?"
    Строка не попадает в результат. Если у пачки нет параметров, она не появится.
    Когда нужны пачки без параметров — используют `left join` (урок 15).

!!! question "Почему `inner join`, а не просто `join`?"
    `join` без слова `inner` означает то же самое. `inner` пишут для явности.

!!! question "Зачем алиасы `as b`, `as e`?"
    Чтобы не писать полные имена таблиц. `b.emploee_id` короче
    `measurment_baths.emploee_id`.
