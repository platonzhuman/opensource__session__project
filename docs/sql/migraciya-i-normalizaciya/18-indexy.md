# 18. Индексы: почему запросы ускоряются

Когда строк станет много, поиск «в лоб» станет медленным. Индекс — это оглавление
таблицы, по которому база быстро находит нужные строки.

!!! abstract "Цель урока"
    Ты поймёшь, что такое индекс, зачем он нужен столбцам-связям и как посмотреть
    план запроса.

## Шаг 1 · Аналогия с книгой

!!! note "Определение"
    **Индекс** — отдельная структура, которая хранит отсортированные значения столбца
    и ссылки на строки. Поиск по индексу похож на поиск по оглавлению: не листаем всю
    книгу.

!!! question "Сделай"
    Что быстрее: найти главу по оглавлению или перелистать всю книгу?

??? success "Проверить"
    По оглавлению. Индекс — то же самое для базы: не читаем все строки, а сразу
    переходим к нужным.

## Шаг 2 · Посмотри план запроса

```sqlplay
-- @seed artillery
explain
select * from measurment_input_params where measurment_bath_id = 1;
```

!!! question "Сделай"
    Найди в выводе слово `Seq Scan` или `Scan`. Что оно значит?

??? success "Проверить"
    `Seq Scan` — последовательное чтение всей таблицы. Пока строк мало, это нормально.
    На больших объёмах база выберет `Index Scan`, если индекс есть.

## Шаг 3 · Создай индекс

```sqlplay
-- @seed artillery
create index ix_mip_bath_id on measurment_input_params (measurment_bath_id);

explain
select * from measurment_input_params where measurment_bath_id = 1;
```

!!! question "Сделай"
    Изменился ли план запроса?

??? success "Проверить"
    На маленькой таблице база может всё ещё выбрать `Seq Scan` — это дешевле для
    нескольких строк. Индекс начинает выигрывать на больших данных. Важно: индекс
    **создан** и будет использован при росте таблицы.

## Шаг 4 · Зачем индексы столбцам-связям

Внешние ключи почти всегда участвуют в `join ... on`. Индекс на `emploee_id`,
`measurment_bath_id`, `parameter_type_id` ускоряет соединения.

!!! question "Сделай"
    По каким столбцам логично сделать индексы в нашей схеме?

??? success "Проверить"
    По всем столбцам-ссылкам: `employees.military_rank_id`,
    `measurment_baths.emploee_id`, `measurment_baths.measurment_type_id`,
    `measurment_input_params.measurment_bath_id`,
    `measurment_input_params.parameter_type_id`, `parameter_types.unit_id`,
    `units.base_unit_id`.

## Шаг 5 · Индекс не бесплатен

!!! warning "Помни"
    Индекс ускоряет чтение, но замедляет вставку и занимает место: при каждом
    `insert` база обновляет и индекс. Поэтому индексируют то, по чему действительно
    ищут.

!!! question "Сделай"
    Стоит ли индексировать каждый столбец?

??? success "Проверить"
    Нет. Только те, по которым фильтруют и соединяют. Лишние индексы замедлят запись.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `create index ... on t (col)` | создать индекс по столбцу |
| `explain` | показать план выполнения запроса |
| `Seq Scan` | чтение всей таблицы |
| `Index Scan` | чтение через индекс |

## Откуда числа

Строки `where measurment_bath_id = 1` — из данных. План запроса — реальный вывод
`explain`, а не выдумка.

## Наивные вопросы

!!! question "Индекс гарантирует уникальность?"
    Нет, если он не `unique`. Обычный индекс только ускоряет поиск.

!!! question "Чем `unique` отличается от `unique index`?"
    `unique`-ограничение создаёт уникальный индекс автоматически. Отдельно создавать
    не нужно.

!!! question "Когда индекс точно нужен?"
    На больших таблицах и столбцах с частыми `where`/`join`. На таблице из 25 строк
    эффекта не видно.

??? success "Проверить"

    2. При вставке база должна дописать значение и в индекс.
