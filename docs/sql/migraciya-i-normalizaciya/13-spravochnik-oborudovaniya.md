# 13. Справочник оборудования и типы измерений

В ТЗ два варианта расчёта: `ДМК` и `ВР`. Оборудование — это справочник, на который
ссылаются пачки.

!!! abstract "Цель урока"
    Ты поймёшь, зачем оборудованию отдельная таблица и как посчитать, каким
    оборудованием пользуются чаще.

## Шаг 1 · Оборудование — справочник

```sqlplay
-- @seed artillery
select id, short_name, description from measurment_types order by id;
```

!!! question "Сделай"
    Почему `short_name` и `description` — два разных столбца?

??? success "Проверить"
    `short_name` (`ДМК`) — короткий код для интерфейса и запросов, `description`
    (`Десантный метео комплекс`) — расшифровка для человека.

## Шаг 2 · Название оборудования уникально

На `short_name` наложено `unique`: двух `ДМК` быть не должно.

!!! question "Сделай"
    Предскажи, что вернёт `insert into measurment_types values (3, 'ДМК', 'дубль');`

??? success "Проверить"
    Ошибку `unique` — короткое имя `ДМК` уже занято.

## Шаг 3 · Сколько пачек на оборудование

```sqlplay
-- @seed artillery
select
    m.short_name as оборудование,
    count(b.id)  as пачек
from measurment_types as m
inner join measurment_baths as b on b.measurment_type_id = m.id
group by m.short_name
order by пачек desc;
```

!!! question "Сделай"
    Что делает `count(b.id)` и чем отличается от `count(*)`?

??? success "Проверить"
    Считает строки присоединённой таблицы `b`. Здесь разницы с `count(*)` нет, потому
    что `inner join` уже отбросил пары без совпадения.

## Шаг 4 · Найди оборудование без измерений

```sqlplay
-- @seed artillery
select m.short_name
from measurment_types as m
left join measurment_baths as b on b.measurment_type_id = m.id
where b.id is null;
```

!!! question "Сделай"
    Что вернёт этот запрос?

??? success "Проверить"
    Ничего: у каждого оборудования есть хотя бы одна пачка. `left join` тут нужен,
    чтобы поймать оборудование без пачек — полезный приём (подробнее в уроке 15).

## Шаг 5 · Проверь уникальность коротких имён

!!! question "Сделай"
    Попробуй вставить оборудование с коротким именем `ВР` и другим `id`.

```sqlplay
-- @seed artillery
insert into measurment_types (id, short_name, description) values (9, 'ВР', 'дубль');
```

??? success "Проверить"
    Ошибка `unique`: короткое имя `ВР` уже занято. Справочник не даёт завести дубль.

## Что здесь что

| Элемент | Что означает |
| --- | --- |
| `measurment_types` | справочник оборудования |
| `unique (short_name)` | двух одинаковых коротких имён не бывает |
| `count(b.id)` | число пачек у оборудования |
| `left join ... where ... is null` | найти записи без связанных строк |

## Откуда числа

Оборудования `ДМК` и `ВР` — из ТЗ. Число пачек считается по данным `artillery`, а не
задаётся вручную.

## Наивные вопросы

!!! question "Почему бы не хранить оборудование строкой в пачке?"
    Тогда `ДМК` повторится в каждой пачке текстом. Справочник хранит один раз, пачка
    ссылается кодом.

!!! question "Зачем `description`, если есть `short_name`?"
    Для интерфейса: пользователю показывают полное название, а в коде живёт короткий
    код.

!!! question "Что если оборудование удалить?"
    Внешний ключ не даст, пока на него ссылаются пачки.

## Чекпоинт

!!! question "Проверка"
    1. **Предскажи:** что вернёт `select count(*) from measurment_types;`
    2. **Объясни**, зачем `unique` на коротком имени.
    3. **Напиши** запрос: сколько пачек у `ДМК`.

??? success "Проверить"
    1. `2`.
    2. Чтобы не появилось двух разных строк с одинаковым кодом `ДМК`.
    3. `select count(*) from measurment_baths b inner join measurment_types m on m.id = b.measurment_type_id where m.short_name = 'ДМК';` → `3`.
