# 5. Функция расчёта

Вторая функция по заданию: принимает произвольное значение `x` и структуру для
интерполяции, возвращает посчитанное `y`.

!!! abstract "Цель урока"
    Ты напишешь функцию `interpolate(x, segment) → numeric` — формулу из
    урока 4 плюс защиту от опасных случаев.

## Шаг 1 · Сигнатура

```sql
create function public.interpolate(par_x numeric, par_segment public.interpolation_type)
returns numeric
language plpgsql
```

- `par_x` — температура, для которой считаем;
- `par_segment` — структура с четырьмя полями из первой функции;
- результат — одно число: поправка.

!!! question "Сделай"
    Почему второй параметр не `numeric`, а `interpolation_type`?

??? success "Проверить"
    Потому что передаём сразу четыре числа одной структурой — концы отрезка.

## Шаг 2 · Тело — сначала формула

```sql
return par_segment.y0
     + (par_x - par_segment.x0) * (par_segment.y1 - par_segment.y0)
                                / (par_segment.x1 - par_segment.x0);
```

Это в точности формула из урока 4, только поля берутся у структуры.

## Шаг 3 · Два опасных случая

Посмотри на формулу ещё раз. Она делит на `x1 - x0`. Когда это плохо?

1. **`x1 = NULL`** — последняя точка таблицы (`40 / 4.5`): выше ничего нет,
   интерполировать не с чем. Возвращаем `y0`.
2. **`x1 = x0`** — вырожденный отрезок: деление на ноль. Такой отрезок появится
   на границе «ниже 0» (урок 6). Тоже возвращаем `y0`.

```sql
if par_segment.x1 is null or par_segment.x1 = par_segment.x0 then
	return par_segment.y0;
end if;
```

## Шаг 4 · Собери функцию

```sql
create function public.interpolate(par_x numeric, par_segment public.interpolation_type)
returns numeric
language plpgsql
as $body$
begin
	if par_segment.x1 is null or par_segment.x1 = par_segment.x0 then
		return par_segment.y0;
	end if;

	return par_segment.y0
	     + (par_x - par_segment.x0) * (par_segment.y1 - par_segment.y0)
	                                / (par_segment.x1 - par_segment.x0);
end
$body$;
```

## Шаг 5 · Проверка

```sql
select interpolate(26, get_interpolation_type_correction(26));  -- 2.3
```

Ещё пара проверок руками:

| `x` | ожидание | почему |
| --- | --- | --- |
| 25 | 2 | левый край отрезка — сразу `y0` |
| 30 | 3.5 | правый край — сразу `y1` |
| 40 | 4.5 | сработает защита `x1 is null` |
| 45 | 4.5 | найдётся та же строка 40 — защита снова вернёт `y0` |

!!! question "Сделай"
    Что вернёт функция для `x = 25`? А почему для 40° не будет ошибки?

??? success "Проверить"
    Для 25 — ровно `2` (нижняя граница). Для 40° структура будет
    `(40, 4.5, NULL, NULL)`, сработает проверка `x1 is null` — вернётся `4.5`.

!!! note "Про деление и типы"
    Если бы поля были `integer`, деление `(y1 - y0) / (x1 - x0)` считалось бы
    «нацело» и часть формулы потерялась. У нас всё `numeric` — делится честно.

## Откуда числа

Формула — из урока 4 (вывели из задания). Значения 26 → 2.3, 25 → 2, 30 → 3.5 —
из примеров задания и таблицы.

## Наивные вопросы

!!! question "Почему две функции, а не одна?"
    Разделение ответственностей: первая — «найти данные» (работа с таблицей),
    вторая — «посчитать» (чистая математика). Плюс задание просит именно две.

!!! question "Можно ли было посчитать без структуры, прямо в SQL?"
    Умеючи — да. Но задание учит оформлять логику функциями: вызывать удобно,
    структура гарантирует, что четыре числа не перепутаются местами.
