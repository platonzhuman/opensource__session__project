# 2. Отрезок по температуре

Интерполировать можно только **между двумя соседними точками** таблицы. Значит,
задача функции — по температуре найти эти две точки: нижнюю и верхнюю.

!!! abstract "Цель урока"
    Ты научишься выбирать нужный отрезок таблицы корректировок запросом:
    пара «нижняя граница» и пара «верхняя граница».

## Шаг 1 · Таблица корректировок

```sql
select * from calc_temperature_correction order by temperature;
```

| temperature | correction |
| --- | --- |
| 0 | 0.5 |
| 5 | 0.5 |
| 10 | 1 |
| 20 | 1 |
| 25 | 2 |
| 30 | 3.5 |
| 40 | 4.5 |

Каждая строка — точка. Между соседними точками — отрезок прямой, на нём и
интерполируем.

## Шаг 2 · Что нужно для 26°

Для 26° нижняя точка — `(25, 2)`, верхняя — `(30, 3.5)`. То есть:

- `x0 = 25`, `y0 = 2` — нижняя граница температуры и её поправка;
- `x1 = 30`, `y1 = 3.5` — верхняя граница.

Это и есть «параметры для интерполяции» из задания.

!!! question "Сделай"
    Какие четыре числа нужны для 23°?

??? success "Проверить"
    `x0 = 20, y0 = 1`, `x1 = 25, y1 = 2`.

## Шаг 3 · `lead` — берём следующую строку

`lead(temperature) over (order by temperature)` — это «температура следующей
строки». Подзапрос превращает таблицу точек в таблицу отрезков:

```sql
select temperature as x0,
       correction  as y0,
       lead(temperature) over (order by temperature) as x1,
       lead(correction)  over (order by temperature) as y1
from calc_temperature_correction;
```

| x0 | y0 | x1 | y1 |
| --- | --- | --- | --- |
| 0 | 0.5 | 5 | 0.5 |
| 5 | 0.5 | 10 | 1 |
| … | … | … | … |
| 40 | 4.5 | *пусто* | *пусто* |

!!! question "Сделай"
    Что вернёт `lead` у последней строки?

??? success "Проверить"
    `NULL` — следующей строки нет. Это ещё пригодится для границы «выше 40».

## Шаг 4 · Правило выбора строки

Нужна строка-отрезок, которая «накрывает» температуру `t`:

- нижняя граница не выше `t`: `x0 <= t`;
- верхняя граница строго выше `t`: `x1 > t` — или верхней нет вовсе: `x1 is null`.

```sql
where t.x0 <= par_temperature
  and (t.x1 > par_temperature or t.x1 is null)
order by t.x0 desc
limit 1;
```

`order by ... desc` + `limit 1` — страховка: если кандидатов несколько
(например, `t = 25` лежит на стыке отрезков), берём самый правый, который
**начинается** в этой точке: `[25–30]`, а не `[20–25]`. Для интерполяции на
стыке без разницы, но правило должно быть однозначным.

!!! tip "Правило"
    Ищем «ступеньку лестницы» под температурой: нижняя ≤ `t`, верхняя > `t`.

## Шаг 5 · Трассировка

| `t` | кто проходит условие | победитель |
| --- | --- | --- |
| 26 | `x0 ≤ 26` — пять строк, но `x1 > 26` — только (25…) | **25 / 2 / 30 / 3.5** |
| 30 | `x0 ≤ 30` — всё до 30, `x1 > 30` — только (30…) | **30 / 3.5 / 40 / 4.5** |
| 45 | `x0 ≤ 45` — все, `x1 > 45` — нет, спасает `x1 is null` | **40 / 4.5 / пусто / пусто** |
| -5 | `x0 ≤ -5` — ни одной строки | ничего (разберём в уроке 6) |

!!! question "Сделай"
    Какой отрезок найдётся для 40°? А для 10°?

??? success "Проверить"
    Для 40° — `(40, 4.5, NULL, NULL)` (сверху уже нет). Для 10° — `(10, 1, 20, 1)`.

## Откуда числа

Таблица `calc_temperature_correction` — из класса (та же идея, что Таблица 1
ТЗ). Пример с 26° — из задания.

## Наивные вопросы

!!! question "Почему `>` для верхней, а не `>=`?"
    Чтобы отрезок был определён однозначно: у 25° есть выбор между `[20–25]` и
    `[25–30]`, и правило «верхняя строго выше» вместе с `order by x0 desc`
    выбирает второй вариант. Для интерполяции на стыке результат одинаков, но
    правило не должно давать двух ответов.

!!! question "`into` — это куда?"
    В твою переменную-структуру: одна строка результата раскладывается по
    полям. Если запрос вернул пусто — все поля останутся `NULL` (см. урок 6).
